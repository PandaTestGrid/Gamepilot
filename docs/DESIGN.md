## 1. 定位

**一句话**：Airtest 的交互手感 + 游戏挂机需要的状态感知与自愈能力，装进一个 Tauri 桌面 App。

### 目标（做）
- 面向**长期无人值守运行**的游戏自动化（挂机、刷本、日常），不是测试用例。
- 录制操作即产出**状态图**（节点/边/恢复边），而非产出线性脚本。
- 调试时能看到**识别过程本身**：分数、投票、转换失败原因、时间轴回溯。
- 安卓（scrcpy）+ Windows PC 游戏（同 DSL 双平台）。

### 非目标（不做）
- 不做注入 / 内存读写 / 反反作弊 —— 纯外部「看屏幕 + 模拟输入」。
- 不做通用 App 自动化测试平台（不做 Web/小程序/iOS）。
- 不做云真机调度平台（自用工具，先单机多开）。
- M1~M3 不做多设备批量（架构留位，UI 不出现）。

## 2. 从 AirtestIDE 继承什么、改什么

AirtestIDE 布局（官方文档核实）：顶部菜单栏 + 5 个可拖拽 dock 窗口
—— 左侧 Airtest 辅助窗 / Poco 辅助窗、中间脚本编辑窗、下方 log 窗、设备窗；
连上设备后辅助窗的录制快捷键点亮，录制结果落到脚本编辑窗；布局可拖拽、自动记忆、可恢复默认。

| 维度 | AirtestIDE | GamePilot | 为什么改 |
|---|---|---|---|
| 布局骨架 | 5 个可拖拽 dock 窗 | **三栏默认**（画面 \| 状态图 \| 事件）+ 可拖拽分栏 + 独立窗口 + 布局记忆 | 保留自由度，但默认布局必须"一眼看全"，不让人自己拼 |
| 左侧 | 录制快捷键矩阵（touch/swipe/assert…） | **识别器面板**：模板缩略图墙 + 实时分数 + 阈值滑块 | 快捷键矩阵对图像脚本意义有限；分数与阈值才是天天要调的东西 |
| 中间 | 代码编辑器 | **状态图画布**（节点=界面，边=动作，红边=恢复边） | 产出数据而非代码；改流程不写代码 |
| 右侧 | 设备窗（投屏） | **画面栏**（投屏 + 识别覆盖 + 框选录制） | 录制发生在画面上，画面上必须有实时识别反馈 |
| 下方 | log 窗 | **事件流 + 时间轴**（可拖动回溯最近 60s 帧） | 静态 log 无法回答"刚才为什么没匹配上" |
| 录制产物 | Python 代码 `touch(Template("x.png"))` | **节点 + 边 + 模板素材** | 代码看不懂、改一次崩一次 |
| 录制反馈 | 事后看代码 | **操作即预览**：框选时实时显示匹配分数、生成前可撤销 | 这是交互手感的核心差异 |
| 报告 | HTML 报告 + 录屏 | 运行监控面板（在线）+ 事件流 JSONL（离线分析） | 挂机是持续性运行，不是一次性用例 |

## 3. 核心概念与数据模型

```
Project（一个游戏一个工程）
├── devices[]        连接过的设备（URI + 分辨率 + 备注）
├── graph.json       状态图（唯一真源，人可读、可 git diff）
│   ├── recognizers  识别器：模板/颜色/OCR/自定义 + ROI + 阈值 + 尺度
│   ├── nodes[]      界面状态：id、name、enter[]（判定标签集合）、vote、timeout
│   └── edges[]      转移：when（触发标签）、from/to、action、priority、cooldown、retries、kind(normal|recovery)
├── templates/       模板素材（PNG，按识别器名）
├── runs/            运行记录：events.jsonl + 报告
└── config.json      设备默认值、tick、投票窗口、快捷键
```

关键设计约束（写进代码规范）：
1. **所有坐标归一化到 [0,1]**。像素坐标只在 Controller 内部出现一次。
2. **识别器是纯函数**：`detect(frame, roi) -> Detection[]`，不持有业务状态。
3. **状态机不 sleep 等结果**：动作执行后挂起 pending 转换，下一帧确认，失败可计数重试。
4. **只有一个截图循环**，UI 永远不直接操作设备。

## 4. UI 设计（重点）

### 4.0 设计语言：扁平化

> AirtestIDE 那种 Win32 经典风（凹陷面板、渐变标题栏、多层边框、面板套面板）明确不要。
> 界面只由 **背景色阶 + 1px 描边** 两种手段构成。

| 维度 | 规定 |
|---|---|
| 层次 | 三级背景：`canvas #0f1115` → `panel #161920` → `raised #1c2029`（工具条/输入框/悬停行）；区域分隔一律 1px `#262b36` |
| 圆角 | 控件 4px；面板 / 表格 / 列表行 = **0（直角）**；禁止 >6px |
| 阴影 | **全面禁止**。弹层唯一允许的"浮起"手段 = 1px 描边 + canvas 半透明遮罩 |
| 间距 | 只用 4 / 8 / 12 / 16 四档，不许出现 6/10/14 |
| 字号 | 11 徽标与辅助 · 12 正文与表格 · 13 面板标题 · 15 仅用于页面标题（全局一处） |
| 行高 | 工具栏 36 · 列表行 26 · 底栏 24 · 弹层行 32 |
| 图标 | lucide 线性图标 16px / stroke 1.75；**状态用 6px 色点表达，不用彩色底块** |
| 数字 | 分数、fps、tick 一律等宽数字（`tabular-nums`），刷新时不跳动 |
| 强调色 | 全局唯一强调色 `#4da3ff`，只用于主操作与"当前选中"，其余全部灰度 |
| 交互反馈 | hover = 变底色；focus = 1px accent 描边；disabled = 40% 透明且不响应 hover |
| 动效 | 仅允许 120ms 的底色/透明度过渡；禁止位移、缩放、弹跳；"当前状态"用 1.4s opacity 脉冲 |
| **明确禁止** | 渐变、阴影、玻璃拟态、卡片套卡片、用彩色背景块表示状态、多种圆角混用、图标风格混用、emoji 当图标 |

### 4.2 各面板规格

**A. 顶部条**（28px，界面上唯一的一排：左边设备标签，右端布局 + 引擎状态）

| 分组 | 内容 |
|---|---|
| 设备标签 | 每台「已连接」设备一个标签（状态点 + 名称 + fps）：单击切换活动设备，双击弹独立窗口，悬停出「独立窗口 / 断开」；末尾 `＋` 打开 §4.3 的设备弹层 |
| 运行中计数 | `N 台运行中 · 上限 4 台`（见 §4.6） |
| 布局 | 预设 / 恢复默认布局（别处没有的入口，所以留在这一排右端） |
| 引擎 | `引擎已就绪` / `引擎旧进程 · 重启`：常驻状态 + 一键重启（"改了引擎代码但没重启"的唯一解法） |

**这一排刻意不重复面板里的入口**（同一个功能放两处，用户反馈"顶部的功能都是重复的"）：运行/停止 → 状态图头部（就近，`lib/useRunControl.ts` 一份状态）；框选录制 → 画面面板头的「框选 / 点选」；设备选择器 → 本排的设备标签与 `＋`（以及画面栏空态的「连接设备」、识别读数的「查看设备」）；多开网格 → 画面面板头的「多开 N」；工作流切换 → 右栏「工作区」（点工作流行即切换，`＋` 新建）。

对比 v1 砍掉的：品牌字、设备下拉 / 连接按钮 / 重连、`⌘Z / ⌘Y`、以及画在顶栏里的假 `─ □ ✕`（窗口按钮走**系统原生标题栏**，`tauri.conf.json` 没关 `decorations`）—— 整排独立工具栏因此不再需要，只把"布局 + 引擎状态"并入设备标签条。

**B. 画面栏**

- **顶部「模拟器窗口」条**（28px 标签条，与设备标签条同规格）：左边是 `模拟器窗口` 标签，右边是各屏标签
  `主屏` / `屏<N> 包名`（6px 状态点 + 当前选中底色），末尾只有一个 `+ 添加屏幕`（展开即自动重新枚举，不必再放一个常驻「刷新」；下拉里还有「刷新列表」）。
  模拟器把每个打开的应用放在一块**独立的 Android 屏**上（就是模拟器顶上的标签页），所以这里列的是
  **当前真正打开的窗口**：预留空槽（没有应用落进去的屏）不列、也不能连 —— 否则"开几个都固定几块黑屏"。
  设备选择器里一台模拟器始终只有一行（= 主屏）；附屏只从这个条进入。
  标签点一下 = 切换画面与控制，标签右侧 `✕` = 断开该屏（不会关掉模拟器里的应用）；
  切回本窗口或展开「添加屏幕」会自动重新枚举（模拟器里关掉标签页，这一格就消失）。
- 实时画面（等比缩放，letterbox），叠加：
  - 识别框：**绿=投票已确认 / 橙=单帧命中待投票 / 红=上次失败的位置（半透明残影）**
  - 每个框上方标签：`名称 分数`，低于阈值时不画框只列在读数区
  - 左上角浮层：`node=main tick=142 pending→battle`
- 鼠标悬停 → 十字准星 + 归一化坐标实时读数 `(0.412, 0.536)`
- **画面上的辅助只在「录操作」开着时出现**（正常控制一个都不画，投屏要干净）：
  轻触 = 落点上中心点 + 扩散环（抬手再播一次）；滑动 = 起点实心点 → 虚线 → 终点空心圈 + 方向箭头。
  两者**互斥** —— 滑动抬手时不补点击标记。
  形状带暗色垫层、位置按**实际画面区域**换算（有黑边时不画在黑边上）
- 模式：`框选`（拖矩形）/ `点选`（单击取 3×3 邻域小模板）/ `只读`
- **画面下方一条设备控制条**（28px，跟着画面那一格一起被上下拖）：**只有导航键、居中**
  `返回 / 桌面 / 最近任务`，右侧一行状态提示（"点画面=轻触 · 拖拽=滑动"）。
  设备没连上时整条按钮变灰，hover 说明原因（不搞"点了没反应"）。
  - **它属于"当前设备的投屏框"**：单画面贴在画面框下面；**多开时放进当前设备那一格**
    （画面与元信息栏之间）—— 挂在整个网格下面时看不出这三个键作用在哪台设备上，离画面也远（用户反馈）
  - **按键随平台变**（`features/device/nav-keys.ts`）：iOS 只有 `主页`（引擎把 back/recents
    都映射成 Home，照搬 Android 会让按钮名和实际动作不符）；macOS 本机窗口一个都不摆（没有实体键），
    并写明"没有实体导航键"，而不是留一条点了必报错的按钮
  - **居中靠三栏网格**（左 1fr · 按键 · 右 1fr 放提示）：`flex + justify-center` 会被提示顶偏
  - **App 自己的开关 + 电源不放这条里**：`控制` / `录操作` / `电源` 在**面板头**（和 框选 / 点选 /
    多开 / 读数 并排，`录操作` 开着时才多出 `+等0.5s/1s/3s`；macOS 本机窗口没有电源键就不显示）
    —— 混在导航键里会让人分不清"是 App 的还是手机的"
  - **导航键不放面板头**：它们是"对这台设备做什么"，和画面是一体的；面板头是 `flex-wrap`，
    窄了会换行变高，不会把按钮压成竖排文字
- 底部识别读数表：标签 / 分数 / 状态（稳定·待确认·未命中），点行可高亮对应框
  - **全部 / 命中 切换**（`命中 = state !== 'idle'`，两个按钮都带计数）：识别器一多，
    "这一帧谁在命中"才是要看的信息；筛选状态记在 `ui.store`，切设备不丢
  - **双击标签就地改名**（Enter 保存 · Esc 取消）：改名由引擎**级联改掉所有引用**
    （节点 enter / 边条件 / 动作目标 / `$score`），模板文件名不跟着改
  - **这里不放删除**：这一列是实时监控（分数每帧在跳），销毁性操作摆旁边误点代价太大；
    删除在右栏「识别器」Tab（见 §4.2 D），那里能同时看到缩略图、阈值和"被谁引用"
  - **整区可收起**（点标题，或把上面的横线拖到底）：收起后只留 26px 标题行 + "命中 N"，
    画面拿走全部高度；状态在 `ui.store.readoutOpen`（不能收到 0，见 CONVENTIONS §12.6-6）

**C. 状态图画布**
- 节点：矩形卡片，显示 name + 判定标签数 + 今日进入次数；`enter` 未全部命中时描边变暗
- 边：箭头连线，标签为 `when`；**recovery 边单独用红色、虚线、带⚡，永远画在图上显眼位置**（因为它是自愈能力的关键）
- 当前节点高亮呼吸；pending 目标节点闪烁
- **鼠标反馈（曾经只有 grab 光标、看着像 bug）**：悬停 = 描边提亮到 brand 55% + 底色抬一级（`bg-raised`）；
  拖拽中 = 实线 brand + `cursor: grabbing`；选中 = brand 描边 + `bg-active`（正在下方编辑器里编辑的那个）；
  连线圆点在悬停时跟着变亮（10px 的点单靠自己很难瞄准）。边：可点 → `cursor: pointer`，
  悬停变粗（1 → 2px）、选中最粗（2.5px），三者是"选中 > 悬停 > 默认"的关系
- 边的线宽/颜色是逐条内联，CSS `:hover` 盖不住 →
  边的悬停必须走 React 状态（`hoveredEdge`），规则见 `features/graph/graph.css` 顶部注释
- **画布手势**（以 xyflow **官方为准**，只保留"左键 = 框选"这一处偏离）：
  **滚动 / 双指滑动 = 缩放**（官方默认；之前改成"滚动 = 平移"是过度设计，用户报"滚轮放大缩小没有"），
  **右键拖动 = 平移**（官方支持的 `panOnDrag=[1,2]`；按住时给"小手"光标，见 `graph.css` 的 `.canvas-panning`），
  中键拖 / 空格+拖动也能平移；**左键拖空白 = 框选多个界面**（官方默认要按 Shift，这里按用户要求改掉），
  `Delete` / `Backspace` 删除选中，左下角图例旁出现"已选 N 个界面 · 删除"工具条。
  多选是画布本地状态（`GraphPane.selectedIds`），和"下方在编辑哪一个"（store 的 `selectedNodeId`）分开。
  `panOnDrag` 含 2 时 xyflow 对画布 `contextmenu` 做 `preventDefault`，
  所以右键平移和"右键弹菜单"**不能共存** —— 画布级右键菜单因此不在右键上（节点/边的菜单仍旧）。
- 交互：拖拽布局（**按住即跟手**，松手才写回 `graph.json`，见 CONVENTIONS §12.6-8）、双击节点改名、右键 → 新建/删除、从节点边缘拖出连线并选择 `when` 标签、点击边在右侧显示属性（priority/cooldown/retries）
- 右上：`▶运行/■停止`（唯一入口：运行的是**当前设备**、读的是**当前这份图**）、`+节点`、`自动布局`、`验证`（跑一遍校验：识别器未命中/边不可达/无恢复边）、`JSON`（切到文本视图）
- **右键菜单**（在鼠标所在位置加东西，而不是跑去点面板头）：
  - 空白处 → `新建界面节点`（落在鼠标位置）/ `新建界面节点并挂上第一个模板`
  - 节点 → `加一步操作`（原地动作）/ `加分支`（出现→A、不出现→B）/ `重命名` / `跳到详情面板` / `删除这个界面`
  - 边 → `改这一步的参数`（滚到详情动作区）/ `删除这一步`
- **画布上直接显示模板截图**：节点上画"认得这个界面"的模板缩略图；每条操作的引脚旁画"这一步点的是哪个图标"。
  缩略图走**进程级缓存**（`stores/template.store.ts`）：一张模板只取一次，取到过就不会再消失 ——
  以前每个缩略图各自取图，引擎保存重载的瞬间失败会让它们同时变成"×"（用户反馈"拖动后模板突然都没了"）；
  失败只在"从没成功过"时显示，并且点一下可以重试
- **点击语义**：点节点/边 = **选中（幂等）**，收起只由**点画布空白**负责。
  不要写成 toggle —— 节点内部的空白、文字、改名输入框点一下都会冒泡到节点上，
  toggle 会让"点节点里的东西"把卡片收起来（用户反馈过）
- **菜单/浮层 portal 到 `body`**：节点在 React Flow 变换内时，
  卡片内部的 `position: fixed` 会被这个变换劫持（坐标被缩放平移），菜单会飞到视口外点不到
- **`onPaneClick` 会收到节点/边内点击的冒泡**（须 `closest` 排除节点/边）。
  所以 `onPaneClick` 里必须先 `event.target.closest('.react-flow__node' | '.react-flow__edge')` 排掉，
  否则点节点会"先选中、再被清空"，点节点里的操作更是直接收起
- 点节点里的**某一步操作** = 选中那一步（下方详情切到该边），并且 `selectEdge` **不清节点选中** ——
  节点靠 `selectedNodeId` 摊开引脚，清掉就等于把上下文收起来了
- 节点卡片有 **小/中/大** 三档（画布头部「节点 中」按钮循环切），卡片宽度、字号、缩略图一起缩放，
  选择存 `ui.store` + localStorage
- **节点上就地改配置**：选中节点后直接在其上挂/摘「进入识别器」、`+ 操作`、双击改名；
  参数级编辑仍在下方详情面板（那里有完整的条件/动作/变量）
- **详情区（画布下方那道坞）有显式的 `▸展开 / ▾收起` 控制条**，收起时也显示"正在编辑什么"；
  以前只有"选中自动展开"和"拖横线"两个隐式入口
- **`＋ 添加操作` 是二级菜单**：一级选"做什么"（点击/长按/滑动/等待/按键/输入文字/赋值/调用子脚本），
  二级选"具体怎么做"（点哪个模板 / 长按几秒 / 往哪滑 / 等多久 / 按哪个键 / 给哪个变量赋值 / 调用哪个脚本），
  每类最后都留一项「自定义…（在下方详情里配）」。选二级项 = **这一步建好且参数已带上**。
  **二级菜单里能直接填值**：点击/长按/滑动都有「坐标（相对）」输入行（x/y 归一化 0~1，
  也接受 `50%` 或 `50`；填不全/非法就不建，免得留下点 (0,0) 的废动作）
- **滑动步骤自己分两种方式**：详情面板顶部「方式」选择框切「点对点滑动 / 连续滑动」，只显示该方式的字段
  （点对点 = 常用方向 + 起止点 + 录制单次；连续 = 录制连续 + 轨迹缩略图/点数/清除）；
  方式写进步骤参数 `swipe_mode`，老数据没这个键时按有无 `path` 推断，回放行为不变；
  连续方式录制时按住 Shift 把这一笔锁成起止直线（预览只画直线，写进 `path` 的是共线三点）
- **右键有两层含义，两者共存**（Figma / Unity 的手感）：右键**拖动 = 平移**（光标 `grabbing` 小手），
  右键**只点不拖 = 弹菜单**。xyflow 原生支持（`panOnDrag` 含 2 时它自己判断这次右键是拖还是点）；
  注意光标规则要写在 `.react-flow__pane.selection` **之后** —— 同权重靠源码顺序决胜
  （点击模板时把 `when` + `all_of` 条件一起绑）；建完自动在详情里选中它。
  规则：一级是"要做什么"、二级是"怎么做"，不要把参数全塞一级（扫不动）也不要全丢给详情（太绕）
- **节点卡片按"可点区域 ≥24px"重排**：标题行右侧 `⋯` 菜单（重命名/加分支/删除）收掉散落按钮，
  meta 行给出"id · 次数 · N 步"，操作行 = 缩略图 + 名称 + `▶`(执行) + `✕`(删除)，
  底部一个整行 `＋ 添加操作 ▸`。小字号标签可以小，**可点元素不行**
- **每一步操作都能 `▶` 直接执行、`✕` 删除**：执行走引擎的 `action.run`（先识别一次再执行），
  结果写进事件流；不需要先跑状态机
- **运行态可视化**：当前节点呼吸、待确认目标闪烁、**条件边流动**（matched / 当前界面的 waiting），
  画布左上角一条运行状态条写着"当前在哪 / 下一步走哪条 / 还差什么"
- **右下角：小地图 + `居中` / `−` / 缩放百分比 / `+`**。坐标是界面私有的，节点被拖远或
  引擎回包重排后，没有参照物时看起来就是"节点消失"，小地图给全局、`居中` 一键把全部节点收进视野
- **坐标记忆（`lib/node-positions.ts`）**：引擎不存 x/y，所以界面必须自己记住用户摆的位置 ——
  每次引擎回包（连接/录制/改名/建节点/切脚本）都要把坐标套回去，否则节点会弹回网格
  （用户反馈"拖动后节点消失""右键建节点前面的节点也没了"就是这个）。坐标按
  `脚本目录 + 设备` 记进 localStorage，重启后还在；`重新布局` 显式丢弃记忆
- **节点状态用官方 `useNodesState`**（`applyNodeChanges` 处理 position/dimensions/select），
  不自造"拖动表/尺寸表"：编号 ① 的坑（`adoptUserNodes` 每次重建节点都清 `measured` →
  小地图画不出节点、`nodesInitialized` 反复 false）由官方状态机天然解决。分工是：
  **不在拖动中的节点坐标以 store 为准**（持久真源；"重新布局"这类操作才生效），
  **正在拖动的节点坐标以本地为准** —— 拖动期间引擎每帧都在推实时分数/激活态，同步一旦用
  store 坐标覆盖会导致拖动抖动（见 `graph-drag.test.tsx`）。
  细节：① 重建节点须保留 `dragging` 标记；
  就会覆盖正在拖的节点（就是抖动的直接原因）；② 写回坐标要读**本地最新坐标**，
  不要用 `onNodeDragStop` 回调参数里的 `node.position`（可能落后一帧，会把节点写回起始位置）；
  松手由 `onNodeDragStop` 写回 store，值相同所以不跳。**尺寸由 React Flow 量、同步时带回去**，
  `data` 每次重建（激活态/引脚是活的）
- **连线用官方严格模式**（`ConnectionMode.Strict`，也是 xyflow 的默认值）：
  右圆点(出) → 左圆点(入)。Loose 模式允许从 target 圆点起拖并**交换方向**，
  用户反馈"我选的是左侧的点连接，结果连到左侧去了"就是这个
- 视图控制用官方 `<Controls>` + `<MiniMap>`（不自己画缩放条）
  - 为什么放在图栏头：图 = 脚本数据，运行 = 设备会话的开关，两者绑定但归属不同；放这里体现"跑的就是这张图"，而且任何布局下都在（运行按钮只有这一处，见 §4.2 A）。图栏被双击弹成独立窗口（`?pane=graph`）时，这里就是那个窗口里唯一的运行入口
  - 点运行不打断编辑：`run.start` 只置标志位，录制/改阈值/改边仍会热重载图并保留当前节点与运行态（`DeviceSession.reload_graph()`）
- **中间是 IDE 式的标签条**（`features/graph/GraphTabs.tsx`）：右栏点一张状态图 = 面板头开一个标签，
  一个标签 = 一份状态图（= 一个任务目录）。注意这**不是"同时加载多份图"**：
  引擎同一时刻只加载一个任务目录，点标签就是切目录（会热重载所有设备的状态图）。
  标签上的 ✕ 只关界面、不删文件；关掉当前那张就接相邻那张；全关掉中间显示
  「没有打开的状态图」空态，并给一个「重新打开「X」」的回头路（否则引擎还指着这张图、
  界面却空了，用户会以为图丢了）。打开过哪几张记在 localStorage，重启后还在。
  标签多了横向滚动，**不换行、不压缩标题**

**D. 右栏 Tab：脚本库 / 识别器**

- **脚本库**（第一个 Tab，ADR 0001）：库里每个脚本一行 —— 名称 + `界面 / 步数 / 识别器数`，当前脚本高亮；
  行上悬停出「复制 / 重命名 / 移除」；顶部「新建」开一张空图并切过去。
  一个目录 = 一张状态图（`graph.json` + `templates/`），切图会热重载所有已连接设备的状态图且不打断运行；
  移除 = 移到库根 `.trash/<名字>-<时间戳>/`（可恢复）。
  - 现在是**三层目录树**（工作区 › 项目 › 脚本，`features/library/WorkspaceTree.tsx`）：
    点脚本行 = 切过去，悬停出行内「改 / 副 / 删」；完整契约见 `docs/WORKSPACE-CONTRACT.md`。
  - **删项目**（项目行悬停出的垃圾桶）：一下带走这个项目下所有脚本，所以**就地二次确认**
    （Tauri 的 webview 里 `window.prompt/confirm` 都不可靠，一律内联确认），
    确认后整目录移到工作区根的 `.trash/`（可恢复）。引擎侧只允许删**工作区根的直接子目录**
    （`workspace.delete_project` 的护栏：工作区根本身、更深的路径、工作区外面一律拒绝）；
    删的正是当前脚本所在的项目时，自动切到树里剩下的第一个脚本。
- **识别器**：缩略图墙 + 实时分数条 + **阈值滑块（拖动即时重算当前帧，画面上的框同步变化）** + 类型徽标（模板/颜色/OCR）。
  - **删除的唯一入口**（行尾「删」）：这里能同时看到缩略图、阈值和"被谁引用"，
    是"看清代价再删"的地方（画面栏那列是实时监控，不放销毁性操作）；
  - **被引用时按钮置灰**，同一行写出 `正在被引用：新界面（node_1）、界面1（n_1）、e_ai（判断条件 + 动作目标）`
    —— 引用关系由 `lib/recognizer-usage.ts`（纯函数）算，规则必须和引擎
    `session.py: remove_recognizer` 一致（否则"界面说能删、引擎说不能删"）；重名节点带 id；
  - 删除 = spec + `templates/<名字>.png` 一起清掉，引擎返回新图直接换掉本地图

**D2. 底部调试抽屉**（事件流 / 日志 / 控制台 / 时间轴，收起 28px，高度可拖）

- 事件流：类型着色 —— `node_entered` 蓝、`edge_matched` 绿、`recovery` 橙、`*_failed`/`error` 红；
  过滤：只看失败 / 只看恢复 / 只看设备
- 日志：引擎（`engine.log` 通知）与界面（`devLog`）混排，按级别过滤（全部 / 信息+ / 警告+ / 错误），自动滚底
- 控制台：手发一条 RPC 看返回（`engine.ping` / `device.list` / `graph.get` …），用来判断"是哪一层坏了"
- 时间轴：最近 60s 的帧序列（M4 接真实环形缓冲；拖动时画面栏切换为历史帧，**只读**，不驱动设备）

**E. 底栏（= 抽屉那条 28px 状态行）**
- 左：`node / tick / vote 进展 / link / 截图 fps / 截图耗时 / 输入延迟 / run 状态` + 最后一条事件摘要
- 右：四个抽屉 Tab + 「抽屉/收起」开关（点同一个 Tab = 收起）
- 任一指标异常变红（fps<3、截图>200ms、连续 5 帧无识别）
- **小窗口靠"整枚收起"适配，不靠换行**：这一条只有 28px 高，一换行文字就掉到抽屉上面去
  （`link dvt（慢）` 的全角括号前后可断行，实测会折成两行）；按钮被压扁还会变成竖排中文。
  所以每枚指标 `shrink-0 + nowrap`，挤不下时按重要性从低到高整枚收起 ——
  `input` → `capture` → `vote` → `link` → 事件摘要 → `fps` → `tick`，
  而 `node` 与 `run` **永不收起**（"现在在哪 / 跑没跑"是这条里最不能少的两条信息）。
  阈值查的是**状态行自己的宽度**（`@container` + `@max-[...]`，实现见 `layout/StatusBar.tsx`），
  不是窗口宽度：真正决定放得下放不下的是"窗口宽 − 右侧 Tab / 抽屉按钮"。
  右侧按钮组固定不压缩，状态行左右各留 12px（原来是左 12 / 右 8，右边贴着窗口边太挤）。

#### 4.3.3 连接状态机（每个条目独立）

```
discovered ──连接──▶ connecting ──成功──▶ connected
    ▲                     │                   │
    │                     │ 失败/超时          │ 断线（adb 掉线 / 游戏崩溃）
    └── 重新检测 ◀── failed ◀──────────────────┘
```

- 阶段文案必须具体，让人知道卡在哪：`adb 连接中…` → `读取分辨率…` → `首帧截图…` → `已连接 1080×1920 · 11fps`。
- `connecting` 超过 8s 判失败并给出原因（设备离线 / 未授权 / 端口被占用）。
- `connected` 后 5s 心跳；掉线自动重连（最多 3 次，间隔 1/2/4s），期间设备标签条的状态点转黄，事件栏写入 `device_lost` / `device_reconnected`。

#### 4.3.4 交互细则（决定手感的部分）

| 场景 | 行为 |
|---|---|
| 打开弹层 | 先渲染本地缓存的列表（0 延迟），后台再扫描；扫描结果原地替换，不闪空态 |
| 扫描 | adb 设备 + Windows 可见窗口 + 内置 Mock；扫描中的行显示骨架条，**不显示假数据** |

| 切换设备 | 直接点另一条目的「连接」，旧的自动断开（同时只允许一个活动设备）；有未保存录制时先确认 |

| Windows 窗口 | 只列有标题的可见窗口；把「搜索窗口」改成**让用户直接把准星拖到目标窗口上**，比从标题列表里挑可靠 |

### 4.6 多设备与多窗口

**结论：要，而且是一等公民。** 挂机场景天然是多开（一台手机 + 一个模拟器 + 一个 PC 窗口），
所以布局与数据模型从一开始就按"N 台设备"设计，而不是先做单设备再改。

**数据模型**

| 概念 | 说明 |
|---|---|
| `DeviceRuntime` | 一台设备：id / name / uri / kind / status / resolution / fps / error+suggestedFix |
| 活动设备 | 同时只有一个，决定中央状态图显示**谁的运行态**、事件流、识别器、底栏指标显示谁 |
| **脚本图（一份）** | 状态图 = **项目（脚本）目录里的 `graph.json`**，**跟设备无关**：A 上录的流程，B 连上就能跑。工程结构、节点、边、识别器都存在这里 |
| 每设备运行态 | 当前节点 / 待确认目标 / 各识别器分数 / 访问次数 —— 只属于"这台设备这次运行"，不写回脚本 |
| 每设备事件桶 | `events[deviceId]`：事件按设备分桶，标签切换时整栏跟着切 |

> 界面实现：`graph.store` 里脚本那份永远存在 `SCRIPT_SCOPE` 下（没连设备也能看、能编辑），
> `graphs[deviceId]` 只是它的**显示缓存**（叠了那台设备的实时分数）；
> 读的时候用 `graphForDevice(state, activeId)`（设备那份没有就退到脚本）。
> 写操作一律走**项目级** `graph.*`（不带 `deviceId`）→ 引擎落盘 `graph.json` + 让所有会话热重载。

**界面**

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ● SM-G9980 11fps │ ● MuMu Player 12 9fps │ +  2 台运行中 · 上限 4 台 │ 布局 · 自检 │ ← 顶部条
├───────────────────────────┬────────────────────────────┬─────────────────┤
│  画面（活动设备）          │  状态图（活动设备）         │ 事件 · 识别器    │
│  多开按钮 → 网格视图       │  切标签即换图               │ 按设备分桶       │
└───────────────────────────┴────────────────────────────┴─────────────────┘
```

- **设备标签条（= 顶部条）**：每个已连接设备一个标签（状态点 + 名称 + fps）；单击切换活动设备，双击弹成独立窗口，`+` 加设备；右端是「布局」与「引擎状态」（界面上唯一的一排，独立顶栏已去掉，见 §4.2 A）。
- **多开网格**：≥2 台已连接时，画面栏可切 1×N → 2×N 网格；每格标题栏显示设备名与 fps。
  **每格画面都是可交互画面**（与单画面共用 `ScreenSurface`，同一套坐标换算 / 手势判定 / 反馈）：
  当前设备的格子点 = 轻触、拖 = 滑动，框选/点选也能直接在格子里拖（草稿写进那一台的状态图）；
  点**别的**格子第一下只切为活动设备、不发触控（挂机场景里"只想换一台看"远多于"要点它"，
  直接发触控就是误触游戏），切好后再操作；格子顶栏/底栏点击 = 纯切设备。
  **例外**：活动设备不在网格里（它掉线了）时按下直接控制 —— 否则每一格的第一下都被吞掉，
  又会变成"点了没反应"。
  录制草稿带 `deviceId`（`beginDraft` 时按下哪一格就记哪一台，`commitDraft` 照它落盘）：
  在 A 上框完再点 B 看一眼，确认时仍然写进 A 的图；草稿那台掉线时表单由兜底浮层兜住。
  多开格子里画面区须单独处理指针（勿整格 `<button>` 吞事件）→
  控制模式开着点上去既不轻触也不滑动、框选/点选静默失效（用户报「设备多开时候点击功能失效」）。
- **独立窗口**：`open_pane_window(pane, deviceId)` → 新窗口 URL `?pane=screen&device=dev-a`，只渲染那一栏。典型用法：画面丢到第二块屏，主窗口留状态图与事件；**关窗不影响运行**。
- **布局记忆**：三栏宽度存 localStorage（`gamepilot.layout.v1`），下次启动恢复。

**运行性能（M1 起必须遵守）**

| 规则 | 原因 |
|---|---|
| 活动设备全速（8~15fps），非活动设备降到 1fps 缩略图 | N 路投屏同时全速会把解码/GPU/带宽吃满 |
| 每个设备一个独立捕获循环，**互不共用线程** | 一台设备卡住（adb 超时）不能拖慢其它设备 |
| 默认活动设备上限 4 台，超出提示 | 自用工具的合理边界；数值可配置 |
| 事件与帧都带 `deviceId`，UI 只渲染活动设备的高频信息 | 避免 N 台设备的帧把前端压死 |

### 6.2 进程与通信

```
┌─ Tauri 2 桌面壳（Rust） ──────────────────────────────────────────┐
│ 窗口 / 托盘 / 全局快捷键 / 文件对话框 / 布局持久化 / 自动更新        │
│  └─ WebView: React + TS + Tailwind v4 + shadcn/ui                  │
│      画面栏 · 状态图画布(React Flow) · 事件流 · 识别器面板 · uPlot   │
└───────────────────────────────┬───────────────────────────────────┘
                                │ JSON-RPC 2.0 over stdio（NDJSON 分帧）
┌───────────────────────────────▼───────────────────────────────────┐
│ Python 引擎（sidecar，PyInstaller 单文件）                          │
│  devices/   Mock · Android(scrcpy) · Windows(DXGI + 虚拟 HID)       │
│  core/      归一化几何 · Frame 协议 · Recognizer · Graph · Engine   │
│  rpc/       RPC 方法 + frame/detection/event 流式通知               │
│  只负责「感知 + 决策 + 执行 + 事件」，不含任何 UI 逻辑               │
└───────────────────────────────────────────────────────────────────┘
```

- **传输**：JSON-RPC 2.0 over stdio，M1 定 NDJSON 分帧（实现最简单、易抓包调试）。
- **帧推送**：独立 `frame` 通知。M1 用 base64 JPEG，M3 评估独立管道 / 共享内存 / H.264 分片。
- **崩溃策略**：Rust 侧守护 sidecar，异常退出自动重启并恢复「当前 graph + 运行状态」，UI 无重连逻辑。
- **为什么不用本地 HTTP/WS**：不占端口、无端口冲突、不被防火墙拦；代价是浏览器无法直连调试引擎（用 `python -m gamepilot.rpc --stdio` 的 CLI 兜底）。
- **进程隔离的额外收益**：引擎崩了 UI 不死。挂机工具这点很重要。

## 7. 状态图 DSL 草案

```jsonc
{
  "version": 1,
  "resolution": [1280, 720],          // 录制时的设备分辨率，仅作参考（坐标是归一化的）
  "defaults": { "tick_ms": 120, "vote": 2, "transition_timeout_ms": 4000 },
  "recognizers": {
    "main_start":  { "type": "template", "template": "templates/main_start.png",
                     "threshold": 0.82, "roi": [0.3,0.35,0.4,0.2], "scales": [0.75,1.0,1.25] },
    "popup_ok":    { "type": "template", "template": "templates/popup_ok.png",
                     "threshold": 0.88, "search": "full" },   // 整帧找：确定按钮可能出现在任意位置
    "battle_hp":   { "type": "color", "target_bgr": [90,200,70], "tolerance": 35,
                     "roi": [0.1,0.12,0.5,0.035], "min_pixels": 200 },
    "settle_text": { "type": "ocr", "expected": "结算", "threshold": 0.6 }
  },
  "nodes": [
    { "id": "main",   "name": "主界面", "enter": ["main_start","main_shop"], "vote": 2 },
    { "id": "battle", "name": "战斗中", "enter": ["battle_hp"], "timeout_ms": 20000, "timeout_edge": "e_settle" }
  ],
  "edges": [
    { "id": "e_start", "from": "main", "to": "battle", "when": "main_start",
      "priority": 10, "retries": 2, "action": { "type": "click", "target": "main_start" } },
    { "id": "e_settle", "from": "battle", "to": "main", "when": "settle_text",
      "priority": 10, "action": { "type": "click", "target": "settle_text" } },
    { "id": "r_popup", "kind": "recovery", "when": "popup_close",
      "priority": 100, "cooldown_ms": 800,
      "action": { "type": "click", "target": "popup_close" },
      "note": "任何界面下都能打断并关闭的弹窗" }
  ]
}
```

运行语义（必须写进文档+测试）：
1. 每帧：识别所有 recognizer → 投票过滤 → 判定当前节点（enter 全中）
2. **recovery 边优先于一切**；执行后进入 settle 阶段，等触发标签消失再重新定位节点
3. 节点内选优先级最高的可执行边 → 执行动作 → 挂起 pending → 下一帧确认目标节点 → 超时按 retries 重试 → 再失败发 `transition_failed`
4. 不知道自己在哪里 → 全局重新定位（这是挂机断线自愈的基础）

### 模板的搜索范围（`search`）

`roi` 的语义是**搜索窗口**，不是"模板必须长在这里"：

| spec | 行为 | 适用 |
|---|---|---|
| `roi` + 不写 `search`（默认 `region`） | 只在 `roi` 内找 | 固定 UI、界面判定（和老版本完全一致） |
| 不写 `roi` | 整帧找（引擎本来就支持） | 手工编辑的 DSL |
| `roi` + `"search": "full"` | **忽略 `roi`，整帧找**；`roi` 保留，切回 `region` 时复用 | 弹窗「确定」、飘浮按钮等位置不固定的目标 |

**搜索范围按「步骤」执行，模板上的 `search` 只是默认值。** 步骤链的 `click` / `hold` /
`wait` / `cond` 的 params 可以写 `"search": "region" | "full"`：

- 写了就用这一步的值（同一张模板 A 步区域搜、B 步全屏搜）；
- 没写 / `"auto"` 就用模板默认（录制时勾的「全屏（模板默认）」）；
- 引擎在每拍按当前步骤把覆盖传给 `perceive()`；同一拍里跨到下一步时，如果范围变了会按需
  重识别一次（`_apply_step_search`），不会拿上一步的检测结果凑合。

命中后 `Detection.rect` 是目标**当前**位置，点击仍然点得准（点击用识别框中心，不读录制坐标）。

全屏搜索的两条硬约束：

1. **性能**：1080p 整帧直接 `matchTemplate` 单尺度实测 45~75ms（ROI 内只要 0.3ms）。
   引擎对搜索区域 ≥ 640×480 的模板走「1/2 降采样粗搜 → 候选窗口原分辨率复核」，
   实测降到 ~15ms；最终分数与位置仍由原分辨率那一步决定。小区域（局部判定）不启用近似。
2. **歧义**：整帧搜索会出现两个同分且位置明显不同的候选。此时 Detection 带 `ambiguous: true`，
   界面画虚线框并提示；**点击动作会直接失败**而不是猜一个
   （提高阈值 / 把搜索范围改回原区域 / 用坐标点击都可解决）。

模板裁剪要贴紧目标：带背景的模板换到另一块背景上照样匹配不上（模板匹配比的是整块像素）。
纯色区域会自动降级成颜色识别器，颜色识别不支持整帧搜索，`search` 对它无效。
