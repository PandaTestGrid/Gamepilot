# 行为树与录制执行流程

2026-10-12。已按用户确认的方案实现；实现决策见 [ADR 0002](../adr/0002-behavior-tree-recorded-flows.md)。

继续使用现有 React Flow、设备画面、录操作和素材库。正式改动集中在中间画布与下方详情，沿用原来的深色扁平风格。UE 的调度概念用于组织任务，录制产生的输入保留显式顺序。

## 两层交互

行为树总览包含 Sequence（依次执行）、Selector（失败后尝试下一个）、条件、任务和有界 Repeat。任务处于 running 时保留游标；Selector 采用有记忆的顺序选择，不会每帧重新抢占当前任务。

双击任务或在任务选择器中进入其录制子流程。白色执行引脚连接设备操作、等待识别、固定等待、条件分支、设置黑板、子流程调用、返回和有界循环。完成、失败、超时、是、否等出口有文字标签；同一出口最多一个后继。素材和黑板引用在参数与节点中显示。

下方详情同时显示任务内部步骤与选中步骤配置。编号用于定位，实际先后以连线为准。配置包含动作定位、坐标或黑板参数、滑动终点与时长、按键与文本、识别组合条件、确认帧数、超时、出口、执行前确认、恢复后的确认以及原始录制证据。

## 录制与编辑

在空工作流点击启用，或在设备画面开启录操作，即使用 v2 模型。每次手势和按键只发送设备一次；设备确认成功后，客户端串行提交会话 ID、事件 ID 和序号。保存失败保留待提交操作，重试沿用相同身份，不再发送输入。

录制默认从任务结尾继续；选中有完成出口的步骤时，在它之后插入并保留原后继。返回结尾前会选用其完成前驱作为插入位置。框选只添加素材，随后在步骤详情明确绑定用途。录制原始坐标、帧号、时间和间隔保存在证据中，绑定素材不隐式回退到坐标。

操作间隔作为录制证据保存，不自动变成固定等待。跨页面后应显式加入等待识别；需要保留固定停顿时使用录操作栏的等待按钮。

停止录制先排空触控和保存队列。流程编辑和一段录制可以整体撤销、重做；撤销后的草稿仍使用当前服务端版本。保存冲突保留草稿并给出错误，不覆盖更新过的文件。

## 执行与恢复

单设备使用一条串行输入通道，等待采用非阻塞游标。任务通过 running/success/failure 向行为树返回。子流程使用调用栈，完成后才推进父流程。黑板是工作流级共享值，每次运行恢复初值；参数可使用 `$变量名` 或 `=表达式`。

识别等待要求后续采样帧与连续命中；超时走超时出口或返回失败，不自动重发上一次点击。固定等待可暂停、单步和取消。循环必须经过有界循环体，结束出口不能构成无界环。

恢复规则监控显式素材条件，独占设备输入，冻结被打断等待的预算，完成后确认触发条件消失及主流程上下文。未开始的操作缺少恢复确认时停止，避免继续误点。恢复次数有上限。

运行固定图、识别器配置和加载的素材快照；编辑仅影响下次运行。运行状态显示配置版本、当前任务/步骤、等待原因、树与步骤结果、黑板值和断点。断点停在输入前；单步只推进一个逻辑步骤。停止不再推进后继，并释放长按触控。
