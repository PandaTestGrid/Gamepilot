# GamePilot

> 把重复交给状态机，把游戏还给乐趣。

GamePilot 是一款面向游戏的**状态机式自动化工作台**：框选界面即可识别，拖拽连线即成脚本，
一台电脑同时驱动 Android、iPhone 与本机窗口 —— 不写代码，画面不出本机。

![GamePilot 工作台与官网预览](./site/preview.jpg)

## 产品介绍

传统按键脚本只会「在某个坐标点一下」，界面一变就卡住。GamePilot 每一拍都在识别「我现在在哪个界面」，
再沿着状态图决定下一步 —— 界面变了、弹窗挡了，它能自己找回来。

- **看得懂画面**：模板匹配 + 颜色识别 + OCR；框选即建识别器，实时分数、阈值、搜索范围可按步骤调；
  命中后点的是模板此刻的位置，不读死坐标。
- **状态机脚本**：节点是界面，边是动作；恢复边优先级最高，弹窗随时打断；运行中热重载；
  一张图就是一份可读的 JSON。
- **录制即脚本**：屏幕上的点击 / 长按 / 滑动直接录成步骤；按键、文本、等待、条件与循环再手动补，
  步骤图始终可读可改。
- **两种滑动**：点对点只记起止点与时长；连续录制真实轨迹，按住 <kbd>Shift</kbd> 锁成起止直线。
  两种方式在步骤面板顶部切换，各用各的字段。
- **拟人执行**：贝塞尔轨迹、时长、末端按住与抖动等参数，可全局或按步骤调整。
- **多设备同屏**：Android（adb → scrcpy）、iOS（17.4+）、本机窗口（macOS）、Mock；
  多开网格里每格都能直接点、直接拖，另有独立窗口与布局记忆。
- **本地优先**：Tauri 2 桌面端 + Python 引擎 sidecar；截图、识别、执行都在本机，画面不上传。

适合：日常挂机、重复日常、多账号 / 多设备、游戏自动化测试。

## 技术栈

- 桌面端：**Tauri 2**（Rust 壳）+ React 19 + TypeScript + Tailwind v4 + shadcn/ui
- 引擎：**Python 3.11+**（感知 / 决策 / 执行 / 事件），作为 sidecar 由壳守护
- 通信：**JSON-RPC 2.0 over stdio**（NDJSON 分帧）
- 设备：Android（adb → scrcpy）、iOS（pymobiledevice3 隧道）、macOS 窗口、Mock

> 当前状态：设备连接、识别、录制、状态机运行、拟人轨迹与多开已可用；安装包与更多机型适配持续完善。

## 快速开始

```bash
# 1. 前端依赖
pnpm install

# 2. 引擎依赖（会创建 engine/.venv）
cd engine && uv sync --extra ocr && cd ..

# 3. 启动桌面 App（开发态，自动拉起 Vite 与 Python 引擎）
pnpm tauri dev

# 只跑前端（浏览器里看布局，RPC 不可用）
pnpm dev
```

首次打开 App，点右上角 **「骨架自检（拉起引擎 + ping）」**：状态变绿即表示
`React → Rust → Python` 三段链路打通。

### 发布安装包（Windows，自带引擎 / adb / OCR）

最终用户**不需要**安装 Python。在开发机执行：

```bash
pnpm install
pnpm build:release
```

安装包在 `apps/desktop/src-tauri/target/release/bundle/`（NSIS `GamePilot_0.0.1_x64-setup.exe` 约 150MiB）。
内置 PyInstaller 引擎 sidecar：**adb**（adbutils）、**scrcpy-server** 3.3.4、**PP-OCRv4** ONNX。
打包细节见 [`engine/packaging/README.md`](engine/packaging/README.md)。

## 怎么用（三步）

```bash
cd ~/Desktop/gamepilot
pnpm install          # 只需第一次
cd engine && uv sync --extra ocr && cd ..   # 只需第一次
pnpm tauri dev        # 启动（窗口几秒后出现）
```

**第 1 步 · 连设备**
设备标签条右侧的 ＋（或画面栏空态的「连接设备」）→ 按来源分类的 Tab 里选一台（安卓 / iOS / 本机窗口 / Mock）→ **点那一行**即连接。
已连接的那一行点一下是**切换当前设备**（多设备时最常用），行尾「断开」才是断开。
macOS 上想操控某个窗口（模拟器、游戏客户端）：切到「本机窗口」Tab，搜 App 名或输句柄，点一下就连。
**模拟器多屏**：MuMu 等模拟器里点开的应用会出现在其它 Android 屏（模拟器顶上的标签页）。
设备选择器里**一台模拟器只显示一行，点击只连接主屏**；画面上方点「添加屏幕」→ 选一个附屏才会连接。
已连接的屏幕在同一栏切换；附屏旁的 × 只断开 GamePilot 连接，不会关闭模拟器应用。
打开新应用标签后展开「添加屏幕」（展开即自动重新枚举，旁边还有「刷新列表」）可发现新屏；逻辑屏号变动时用物理屏 ID 保持会话身份。
连上后设备标签条上多一个标签（当前那台高亮），画面栏开始出现画面。
连不上时界面会出现红条，直接写着原因（例如"未授权：在手机上确认允许 USB 调试"）。

**第 2 步 · 录一个界面元素**
点画面栏的「框选」→ 在画面上拖一个矩形 → 弹层里填名字（会自动建议）→「确定并写入状态图」。
画面栏底部的「识别读数」和右侧「识别器」面板会立刻显示它的**实时分数**。

**画面栏还能直接控制手机**（不用碰手机，坐标按画面算、拖动实时跟手）
控制键就在投屏下面那条：`控制` 开关、`返回 / 桌面 / 最近任务 / 电源`、`录操作`（开着时多出 `+等1s`）。

- 点画面 = 轻触；在画面上拖拽 = **实时滑动**（拖动过程中逐事件发 move，跟手）
- 坐标按**实际画出来的画面**换算：`object-contain` 的黑边不参与控制，
  面板上会画一圈淡边框标出可点区域
- 工具栏右侧是功能键：← 返回 / ⌂ 桌面 / 最近任务 / 电源
- 左下角写「控制」的按钮可以关掉控制（关掉后画面只用于框选/点选录制，不会误触手机）
- 每次手动操作都会记一条事件（`manual_input`），在事件栏能看到坐标与耗时
- 走的是 scrcpy 控制通道：点击 ~0.1ms（`adb shell input tap` 要 ~1030ms）

**多开（同时看多台 + 同时控多台）**
点画面栏面板头的「多开」→ 网格里每台一格（≥4 台排两列）。**每一格的画面都能直接控制**：

- **当前设备那一格**（蓝色边框）：点 = 轻触、拖 = 滑动，和单画面完全一样；
  「框选 / 点选」也能直接在格子里拖 —— 录下来的元素照样落进这一台的状态图
  （框完就算点了别的格子看一眼，确认时仍然写进你框的那一台）
- **别的格子**：点一下**先切为当前设备**（那一下不发触控 —— 免得"只想换一台看"却误触了游戏），
  切好之后再点/拖就是真控制；格子顶栏、底栏点一下也只是切设备。
  若哪一格都没有蓝边框（当前设备掉线了），点哪一格都是直接控制
- `返回 / 桌面 / 最近任务` 这条控制条**就在当前设备那一格里面**（画面下方），
  切到哪台它就跟到哪台 —— 一眼看出按的是谁，不用再低头找网格外面那条
- 每格标题栏有设备名与 fps；想看识别框就双击设备标签把那一台开成独立窗口
- 网格里每台 4~6fps（窗口不可见时 0fps），但控制走的是独立控制通道，**和帧率无关**

**第 3 步 · 跑起来**
再录一个"下一个界面"的元素（或直接在中间状态图里连边），然后点状态图头的「运行」。
事件栏会出现 `node_entered` → `edge_matched` → `action_executed`，画面上的识别框按"已确认（绿）/ 待确认（橙）"变色。

> 灰色不可点的按钮把鼠标停上去会说明原因（例如「状态图里还没有节点：先在画面栏点『框选』…」）。

### 坐标这件事（跨设备必须一致）

控制、录制、反馈共用**当前画面的归一化坐标**。现状：

| 设备 | 旋转后控制错位 | 框选能框到画面外 |
|---|---|---|
| Android（scrcpy） | 曾有：画布尺寸只在握手时读一次 → 已修（每帧同步） | 曾有 → 已修 |
| iOS（隧道 DVT） | 曾有：DVT 缓冲变成横屏后就把旋转省了，横屏点击按竖屏送（方向码 3/4 的常量名也写反过）→ 已修：digitizer 固定在物理竖屏玻璃，按界面方向旋回，方向码过期时按画面比例兜底 | 曾有（前端共用代码）→ 已修 |
| macOS 窗口 | 无旋转概念；同类问题是"窗口被移动/改尺寸" → 手势开始时刷新几何 | 曾有 → 已修 |
| Mock | 无 | 曾有 → 已修 |

### macOS 本机窗口（把桌面应用的窗口当设备）

| 能力 | 实现 |
|---|---|
| 枚举 | `CGWindowListCopyWindowInfo` → **句柄**（`kCGWindowNumber`）、pid、App、标题、位置尺寸 |
| 选窗口 | 设备面板里展开「本机窗口（macOS）」→ 点一个直接连；也可以**直接输句柄**（`Mac:///?window=89`） |
| 抓图 | `CGWindowListCreateImage(…IncludingWindow, 句柄)` —— 只抓这个窗口，被别的窗口挡住也不影响 |
| 控制 | `CGEvent` 鼠标/键盘，坐标 = 窗口原点 + 归一化×窗口尺寸（屏幕点坐标，Retina 不影响） |

**控制方式两种**（`Mac:///?window=89&post=pid|global`）：

| 模式 | 你的鼠标/焦点 | 可靠性 | 实测 |
|---|---|---|---|
| `pid`（默认） | **完全不动**（CGEventPostToPid 直投目标进程） | 部分 App 会忽略直投事件 | 鼠标位置完全不变 ✓；Finder/活动监视器不响应 ✗ |
| `global` | 会激活目标 App、指针被挪到点击处（**手势结束自动放回原处**） | 和真人操作一样可靠 | 点击生效（内容差异 8.18）✓；鼠标回到原位置 ✓ |

想要"一边用它一边干活"就用默认的 `pid`；发现点了没反应就换 `global`。

**需要两个系统权限**（缺了会明确报错）：

- 系统设置 → 隐私与安全性 → **屏幕录制**：给运行 GamePilot 的程序打勾（否则抓图是空白）
- 系统设置 → 隐私与安全性 → **辅助功能**：控制别人的窗口需要它

实测（Finder 窗口 #89，920x436）：抓图 ✓、点击后画面差异 8.12 ✓、方向键差异 7.74 ✓。

**Windows 同构**：同一套控制器接口，把枚举/抓图/输入换成 `EnumWindows` / `PrintWindow`+`BitBlt` / `SendInput`
即可，上层（设备列表、坐标映射、脚本、录制）不用动。当前机器是 macOS，Windows 未实现也未验证。

### iOS（仅 17.4+，已在 iPhone 15 Pro Max / iOS 26.6.2 实测）

| 能力 | 实现 | 实测 |
|---|---|---|
| 投屏 | pymobiledevice3 用户态 RSD 隧道 + **DVT 截图循环** | 2796×1290、128ms/张 ≈ **7.8 fps** |
| 控制 | 同一条隧道上的 **CoreDevice HID**（触摸 0..65535 / Indigo 按键 / 虚拟键盘） | Home 键、点击、滑动都实测生效 |
| 发现 | `pymobiledevice3 usbmux list`，自动过滤低于 17.4 的设备 | iPhone 15 Pro Max（iOS 26.6.2）✓ |

**不需要 sudo、不需要切 USB 配置**（隧道是用户态的，`python -m gamepilot.devices.ios_usb` 可以测绘
每套配置的通路数）。

**为什么不用 QuickTime**：

1. macOS 上 **ffmpeg/avfoundation 看不到** iOS 屏幕采集设备 —— 它属于 Continuity/External 类型，
   进程没有 `NSCameraUseContinuityCameraDeviceType` 声明就被系统隐藏（配置 1~6 全试过）。
2. pymobiledevice3 的隧道投屏 `DisplayService.startmediastream` 在 **iOS 26 上直接报
   "requires iOS 27.0 or later"**。
3. 把设备切到**配置 2 会让 usbmux 通路消失**（配置 2 只有 PTP + 音频 + HID）—— 这才是
   "QuickTime 独占设备、别的连不上"的真实机制。正常数据通路在**配置 6**，本实现不动它。

限制：`UserspaceRsdTunnel` 是进程级单例，**一个进程同时只能带一台 iOS 设备**（多台要拆进程）；
截图循环 ~8fps，适合自动化与模板匹配，不适合当高帧率监控看。

### 工作区 › 工作流（目录）

层级：**工作区（= 你选的一个文件夹，可以有多个）› 工作流（= 一张流程图）**。

- **工作区可以有多个**：右栏点标题行「工作区 …」打开面板，`＋`（⌘O）选一个文件夹 +
  给它起个名字（默认用文件夹名）就是新工作区；用过的都在列表里，点一下切换；
  记在 `config.json` 里，重启还在
- 一个工作区 = 一个目录，**里面什么都不自动建**（没有默认工作流），
  点「＋工作流」**输名字**才建出 `<工作区>/<名字>/{graph.json, templates/}`
- 删工作流 / 删工作区都**不是真删除**：工作流进该工作区的 `.trash/`，
  整个工作区进配置目录下的 `.trash/`，都能捞回来
- 当前工作流在这一栏里高亮显示，点别的工作流即切换（＋ 新建；悬停那一行有重命名/复制/删除）
- 切换工作流会**热重载所有已连接设备的状态图**，运行中也不丢当前节点
- 推荐位置是仓库里的 `workspaces/默认`（面板底部「默认工作区」），但工作区可以选到任何地方；
  `GAMEPILOT_PROJECT_DIR` 指定当前工作流，`GAMEPILOT_WORKSPACE_DIR` 指定当前工作区（测试用）

完整契约（RPC + 界面规矩）见 [docs/WORKSPACE-CONTRACT.md](docs/WORKSPACE-CONTRACT.md) 与
[docs/rpc.md](docs/rpc.md) 的「工作区 / 工作流」一节。

**模板放在哪、叫什么名字**（"我的模板到底存到哪去了"）：

```
<脚本目录>/graph.json                  ← 状态图 = 唯一真源：识别器 / 节点 / 边 / 变量都在这
<脚本目录>/templates/<录制时的名字>.png  ← 录制时裁下来的那一块，一个识别器一个文件
```

- 名字的对应关系**写在 `graph.json` 里**，不是靠文件名猜：
  `recognizers["相机"].template = "templates/相机.png"`（相对脚本目录，所以切脚本不会串）
- **改识别器名字不会改文件名**：`模版1` 的文件可能还叫 `main_region_1.png`。
  文件名只是素材的存放位置，匹配用的是 spec 里的路径；想对上号就看 `graph.json`，
  或者在识别器面板里悬停缩略图看大图
- 复制脚本会把整个 `templates/` 一起复制，两份脚本互不影响

**重名 / 重复了怎么处理**（实测行为）：

| 情况 | 结果 |
|---|---|
| 同一个名字**重录**（哪怕框的是别处） | 覆盖：`templates/<名字>.png` 换成新截图，spec 也换成新的（阈值 / ROI / 搜索范围跟着换），节点的 `enter` 里仍然只有一条 |
| 同一块画面**换个名字**再录 | 两份**独立**文件（内容可能一模一样）：引擎不做内容去重 —— 两个识别器本来就是两个判定条件，各自能单独改阈值 / 删掉 |
| 两个脚本里各有一个同名识别器 | 各在各的 `templates/`，互不影响（路径相对脚本目录） |
| 删掉一个识别器 | 在右栏「识别器」Tab 里删（**只有这一处**）：spec + 它的 `templates/<名字>.png` 一起删。被节点/边引用时按钮**置灰**并写出被谁引用（引擎也会拒绝，双保险） |
| 名字改成另一个已有的 | 引擎拒绝（`已经有同名识别器`），不会出现两个同名条目 |

### 录脚本（把操作直接录成步骤）

1. 连上设备，在画面栏**框选**一个界面元素 → 自动建一个节点（这个界面）
2. 点画面栏的 **「录操作」**，然后在画面上正常操作：
   - 点一下 → 录成一步"点击"（带坐标）
   - 拖一下 → 录成一步"滑动"（带起止点与时长）
   - 「+等1s」按钮 → 录成一步"等待"
3. 换个界面后**再框选一次** → 上一步会自动接到这个新界面（A --动作--> B）
4. 点状态图头的「运行」就是刚录下来的流程；事件栏能看到每一步

开「录操作」时操作照常发到手机上（跟手），只是额外记一步到脚本里。
条件默认是"在源界面才做"，想改成"无条件/限时等待"就点那条边改。

#### 滑动：点对点 / 连续（顶部选择框切换）

滑动步骤面板最上面是**方式**选择框，选哪种就只显示哪种的字段：

| 方式 | 面板上有什么 | 记下来的 |
|---|---|---|
| **点对点滑动** | 常用方向（上/下/左/右）、起点 / 终点、录制单次 | 起止点 + 时长；回放走直线（可开拟人贝塞尔），`graph.json` 不会变长 |
| **连续滑动** | 录制连续、轨迹缩略图 / 点数 / 清除 | 起止点 + 时长 + `path` 轨迹（自动简化到 ≤32 点，卡片显示「连续 N 点」）|

- 两种方式**共用**「时长」：点对点下点「录制单次」= 拖一下就松手；连续下点「录制连续」= 拖出一条轨迹再松手（按住 Shift = 起止直线）。
- 方式存在步骤参数的 `swipe_mode`（`point` / `track`）里：切到「连续滑动」后即使还没录轨迹也不会跳回点对点；老数据没有这个键时按「有轨迹 = 连续滑动」推断，行为不变。
- 从「连续滑动」切回「点对点」会清掉旧 `path`（否则回放仍会走上一把的弧线）；「连续轨迹 N 点」旁的清除按钮只清轨迹、留在连续方式，方便马上重录。
- **「按住」是什么**（只在连续方式出现）：到终点**先别松手**，停一会儿再松（推摇杆、长按拖拽就靠它）。停下那段时间不算进滑动时长，回放时到终点真的按住不动。
  「录制连续」时在终点停 ≥0.2 秒会自动填进「按住」；也手填（`0` = 松手就结束）。点对点录制只记起止点与时长，不记末端按住。
- 拖的时候画面上会跟着长出**轨迹**（这条线就是会写进 `path` 的东西；按住 Shift 时是起止直线），引导条同时报「正在记轨迹：N 点」；步骤面板里还有缩略图。
- 「录制连续」时**按住 Shift** 再拖 = 画直线：屏幕上画的是起止直线，写进步骤的 `path` 也是这条直线上的三点（仍算连续轨迹，可以同时带「按住」）；不按 Shift 才录手指的弯线。
- 「录制单次」拖动时画的是**起止直线**（实际写进步骤的就是这两点），手指拖出的弯线不会被画成轨迹——只有「录制连续」（且不按 Shift）才画真实轨迹。
- **画圈、来回推也算连续滑动**：判定不只看「起点到终点」的位移（画圆时这俩点几乎重合），还看手指实际走过的路程。
- 点录制后左栏画面顶部会出现引导条，在**画面上**拖即可；录错了点引导条右边的「取消」。
- 重录成单次/直线时会顺手清掉旧的 `path` 与「按住」。
- 实时触控通道（scrcpy / iOS / macOS）下「按住」是真按住；只有 adb 兜底通道时会被并进滑动时长，引擎会打一条 warning。

### 判断条件与基础操作

点中状态图里的一条边，底部会出现编辑器：

- **判断条件**：`且(all_of)` / `或(any_of)` / `非(none_of)` 勾选识别器标签，
  外加 `min_score` 分数门槛与 `限时等待ms`（进节点后最多等这么久，超时这条边不走并上报 `edge_timeout`）
- **动作**：点击 / 长按 / 滑动 / 等待 / 按键 / 输入文本；
  点击可以直接选"目标识别器"（跟着识别结果走），也可以用归一化坐标
- 保存后写回 `graph.json` 并热重载，运行中的状态机立刻用新条件

识别器面板里每个模板都有缩略图，**点一下切黑白** —— 黑白就是模板匹配真正用的样子。

**同一个按钮不一定在同一个位置？** 搜索范围**以步骤为准**：

- **本步搜索**：每个点击 / 等待 / 条件步骤都可以单独选「跟随模板 / 原区域 / 全屏」。
  同一个模板，A 步可以只在录制区域找，B 步可以整帧找 —— 这是**步骤的能力**，不是模板锁死的；
- **模板默认**：只作为「跟随模板」时的兜底，在录制浮层勾「全屏（模板默认）」设置；
  步骤面板里不再重复显示这一层。

- 全屏搜索引擎会走「1/2 降采样粗搜 → 候选窗口原分辨率复核」，1080p 单尺度从 45~75ms 降到 ~15ms；
- 命中后点的是模板**当前**的位置，不读录制坐标；
- 同一画面有两个同分且位置不同的目标时，画面栏画虚线框提示，**点击动作会拒绝猜**（提高阈值或改回原区域）；
- 纯色区域会自动降级成颜色识别器，颜色识别固定按原区域找，不支持全屏。
- **框选要贴紧目标**：模板里带会滚动的背景（比如图标后面的壁纸）时，目标一移动就匹配不上；
  目标被屏幕边缘裁掉一部分也认不到。

### 变量（黑板）与参数引用

游戏脚本里同一个值往往要写很多遍（一个坐标、一个阈值、一个重试次数）。变量把它们抽出来共享：

- 状态图面板的「**变量**」页签：加变量、改默认值、选类型（数字/文本/识别器键）
- 动作参数里填 **`$变量名`** 就表示"用这个变量"（例：点击 X 填 `$点击X`）
- 还有个 **`set`（赋值）动作**：`设置变量 次数 = $次数 + 1`，用来计数/改状态

运行期语义：变量每次 `运行` 都从默认值开始；`set` 改的是**这一次运行**的值（引擎会回传到状态里，
面板上显示成"当前 …"）。存储上完全增量：`graph.json` 多一段 `variables`，老脚本不带它照样跑。

### 图编辑器

- **右键**：空白处 → 新建界面节点（落在鼠标位置）；节点 → 加一步操作 / 加分支 / 重命名 / 删除；边 → 改参数 / 删除
- **画布上直接看模板截图**：节点上标出"认得这个界面的模板"，每条操作旁标出"这一步点的是哪个图标"
- **节点上就地改配置**：选中后就能挂/摘「进入识别器」、`+ 操作`、双击改名（参数细调在下方详情）
- **+ 节点**：新建一个空节点，然后在底部给它挂识别器
- **拖节点**：按住就跟着鼠标走（拖动过程中不写盘）；**松手才写回 `graph.json`**，运行中也不会打断状态机
- **拖拽连线**：从节点右侧的小圆点拖到另一个节点即可连边（默认条件=源界面的识别器）
- **点节点**：底部出现节点编辑器（改名、挂/摘进入识别器、删除节点；删节点会连带删掉相关边）
- **点边**：底部出现边编辑器（判断条件 + 动作 + 优先级/冷却 + 删除）
- **重新布局**：按网格重排节点（引擎不存坐标，坐标是界面私有的）
- **运行/停止**：只有图栏头那一处（就近）；运行的是"当前这台设备"、读的是当前这份图 ——
  不点运行时引擎照样在识别（框/读数/阈值实时），只是不决策、不发动作；运行中改图不会打断它（热重载保留当前节点与运行态）

### 界面上各区是干什么的

| 区域 | 作用 |
|---|---|
| 顶部条（设备那一排） | 左边是每台已连接设备的标签（单击切换活动设备、双击独立窗口、`+` 加设备）；右端是 **布局菜单（预设/恢复默认）** 与 引擎状态（点击可重试启动）。运行/录制/设备选择器/多开/工作流都在就近的面板里，这一排不再重复放 |
| 设备标签条 | 每台已连接设备一个标签；单击切换活动设备，双击弹独立窗口，`+` 加设备 |
| 左栏「画面」 | 实时画面 + 识别框；**跟着当前设备投屏框的一条设备控制条**（返回 / 桌面 / 最近任务，单画面在画面下方、多开在当前设备那一格里）；下半是识别读数（可上下拖） |
| 中栏「状态图」 | 节点=界面、边=动作、红色虚线=中断处理（recovery）；点边可看属性 |
| ↗ 状态图头 | **运行/停止（唯一入口）**、+ 节点、重新布局 |
| 右栏 | **Tab：脚本库 / 识别器**（识别器是阈值滑块，拖动即时重算分数） |
| 底栏 | node / tick / fps / 截图耗时，异常会变红；右侧四个按钮拉开**调试抽屉** |

**区域都能拖**：栏与栏之间的竖线左右拖 = 改宽度；栏内的横线上下拖 = 改高度
（画面/识别读数、画布/编辑坞、主区/调试抽屉）。比例会记住，下次启动还在；
拖乱了用顶部条右端的「布局 → 恢复默认布局」，或双击任意分隔线让那一栏回到默认比例。
状态图的编辑坞没选中节点/边时会收成一条 28px 提示条，点节点或边自动展开。

**调试抽屉**（底栏右侧四个按钮，或点 Tab 名）：
「事件流」看状态机每一步、「日志」看引擎与界面的原始日志（不用再去翻终端）、
「控制台」手发一条 RPC 看返回、「时间轴」看当前帧/tick/fps。再点同一个 Tab 收起。

**多张状态图 = 多个脚本目录**：右栏「脚本库」里可以新建 / 复制 / 重命名 / 移除脚本，
点一行就切过去（会热重载所有已连接设备的状态图，运行中的不丢当前节点）。
一个目录 = 一张图（`graph.json` + 自己的 `templates/`），互不干扰；
移除是移到库根 `.trash/<名字>-<时间戳>/`，后悔了能捞回来。

### 常见问题

| 现象 | 怎么办 |
|---|---|
| 顶部条一直「引擎未连接」 | 点它重试一次；仍失败则 `cd engine && uv sync --extra ocr`（缺依赖会让引擎起不来），错误详情会显示在它旁边 |
| 顶部条写着「引擎旧进程 · 重启」/「读不到工作区：未知方法: workflow.create」 | 引擎是应用启动时拉起的独立进程，代码更新后它还是旧的：点错误条或顶部条那个按钮**重启引擎**即可（会断开当前设备连接，重连一下）。新增引擎方法的开发者也别忘了把方法名加进 `lib/engine-methods.ts` |
| 设备列表是空的 | 手机没插好或没授权：终端跑 `adb devices`，状态应是 `device` 而不是 `unauthorized` |
| 点「运行」是灰的 | 悬停看原因：没选设备 / 设备没连上 / 状态图里没有节点 |
| 框选之后没反应 | 录制需要先连设备；界面顶部红条会提示 |
| 多开里点画面没反应 | 先看那一格是不是**当前设备**（蓝色边框）：不是的话第一下只切设备，切好后再点才是控制。仍没反应就看顶部红条（设备未连接 / 触控失败），并确认「控制」开关没关 |
| 主屏黑画面 / 附屏暂时没有画面 | 先确认应用仍在对应的 MuMu 标签页，再展开画面上方「添加屏幕」（会自动刷新）。MuMu 预留的空屏槽不算打开的窗口、不能连接；scrcpy 无首帧或断流会**直接报错**，不会拿 ADB 画面或主屏冒充附屏 |
| 画面很卡 / 黑屏 / fps 很低 | 引擎只有 scrcpy 视频通道，正常 30fps；连不上或断流会**直接报错**（不会偷偷换成截图），先看底栏 `link` 的说明，再按提示重连或点「重启引擎」 |
| 录纯色区域（血条之类） | 会自动改用**颜色识别器**（模板匹配对纯色不可靠），事件栏会写明 `mode: color` |
| 工程文件在哪 | 在你选的工作区目录里：`<工作区>/<工作流>/{graph.json,templates/}`，可直接 git diff；`GAMEPILOT_PROJECT_DIR` 切当前工作流、`GAMEPILOT_WORKSPACE_DIR` 切当前工作区 |
| 找不到「添加工作区」 | 右栏标题行点「工作区 …」打开面板，右上角 `＋`（快捷键 ⌘O）就是它；**选完文件夹还要给它起个名字**（默认填文件夹名），确认后才加进列表 |
| 工作区里怎么放流程图 | 点标题行右边的「＋工作流」→ **输名字** → 建出 `<工作区>/<名字>/`（含 `graph.json` + `templates/`）；不会给你自动建任何东西 |
| 删掉的东西去哪了 | 工作流 → 该工作区的 `.trash/`；整个工作区 → 配置目录（`~/Library/Application Support/gamepilot/`）下的 `.trash/`。都是移动，可以捞回来 |

### 性能现状（真机实测：OPPO A57 / Android 6.0.1 / USB 2.0）

| 指标 | scrcpy 通道（唯一通道） |
|---|---|
| 画面帧率 | 解码 ~28fps；按界面需要交付（单画面最多 30fps、多开每台 4~6fps、窗口不可见 0fps） |
| 每次取帧耗时 | 0.3ms（复用已解码帧） |
| 点击 | **0.1ms**（控制 socket） |
| 连接耗时 | 1.6~2.5s |
| 录制一次模板 | ~10ms |
| 三台设备同时投屏 | USB 带宽共享，按 1.3s/台 估算 |

- 只有 scrcpy 这一条通道：jar 推送失败、编码器被占用、Android 版本过低都会**直接报错**，
  不会偷偷换成 adb 截图（那玩意 1fps 且点击要 0.4s，等于把问题藏起来）
- 底栏的 `link` 会显示通道与尺寸（`scrcpy W×H`）
- scrcpy **只在画面变化时才出帧**（静止画面会复用上一帧），所以 fps 会随画面活动浮动
- 界面不需要的帧不会被推：`device.stream` 让前端告诉引擎"这台的画面我看不看、看多少帧"，
  识别与状态机仍在引擎里照常跑 —— 多设备时这是避免卡顿的关键
- scrcpy-server（v3.3.4，Apache-2.0）已收进 `engine/vendor/`，不需要你单独装 scrcpy；
  也可以用 `GAMEPILOT_SCRCPY_SERVER` 指向自己的版本
