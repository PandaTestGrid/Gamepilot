# GamePilot

面向**游戏**的状态机式自动化框架 —— 目标是 Airtest 的交互手感 + 挂机场景需要的状态感知与自愈能力。

- 桌面端：**Tauri 2**（Rust 壳）+ React 19 + TypeScript + Tailwind v4 + shadcn/ui
- 引擎：**Python 3.11+**（感知 / 决策 / 执行 / 事件），作为 sidecar 由壳守护
- 通信：**JSON-RPC 2.0 over stdio**（NDJSON 分帧）
- 设备：Android（adb → scrcpy）、Windows（DXGI + 虚拟 HID）、Mock（离线端到端）

> 当前状态：**项目骨架已完成**（工程配置、规范、契约、三栏布局占位、引擎链路自检）。
> 业务功能按 [`docs/DESIGN.md`](./docs/DESIGN.md) 的 M1~M5 里程碑推进。

## 快速开始

```bash
# 1. 前端依赖
pnpm install

# 2. 引擎依赖（会创建 engine/.venv）
cd engine && uv sync && cd ..

# 3. 启动桌面 App（开发态，自动拉起 Vite 与 Python 引擎）
pnpm tauri dev

# 只跑前端（浏览器里看布局，RPC 不可用）
pnpm dev
```

首次打开 App，点右上角 **「骨架自检（拉起引擎 + ping）」**：状态变绿即表示
`React → Rust → Python` 三段链路打通。

## 怎么用（三步）

```bash
cd ~/Desktop/gamepilot
pnpm install          # 只需第一次
cd engine && uv sync && cd ..   # 只需第一次
pnpm tauri dev        # 启动（窗口几秒后出现）
```

**第 1 步 · 连设备**
顶栏左侧写着「未连接设备」→ 点它 → 按来源分类的 Tab 里选一台（安卓 / iOS / 本机窗口 / Mock）→ **点那一行**即连接。
已连接的那一行点一下是**切换当前设备**（多设备时最常用），行尾「断开」才是断开。
macOS 上想操控某个窗口（模拟器、游戏客户端）：切到「本机窗口」Tab，搜 App 名或输句柄，点一下就连。
连上后顶栏变成设备名，画面栏开始出现画面。
连不上时界面会出现红条，直接写着原因（例如"未授权：在手机上确认允许 USB 调试"）。

**第 2 步 · 录一个界面元素**
点画面栏的「框选」→ 在画面上拖一个矩形 → 弹层里填名字（会自动建议）→「确定并写入状态图」。
画面栏底部的「识别读数」和右侧「识别器」面板会立刻显示它的**实时分数**。

**画面栏还能直接控制手机**（不用碰手机，坐标按画面算、拖动实时跟手）
控制键就在投屏下面那条：`控制` 开关、`返回 / 桌面 / 最近任务 / 电源`、`录操作`（开着时多出 `+等1s`）。

- 点画面 = 轻触；在画面上拖拽 = **实时滑动**（拖动过程中逐事件发 move，跟手）
- 坐标按**实际画出来的画面**换算：`object-contain` 的黑边不参与控制，
  面板上会画一圈淡边框标出可点区域
- 工具栏右侧是功能键：← 返回 / ⌂ 桌面 / 最近任务 / 电源
- 左下角写「控制」的按钮可以关掉控制（关掉后画面只用于框选/点选录制，不会误触手机）
- 每次手动操作都会记一条事件（`manual_input`），在事件栏能看到坐标与耗时
- 走的是 scrcpy 控制通道：点击 ~0.1ms（`adb shell input tap` 要 ~1030ms）

**第 3 步 · 跑起来**
再录一个"下一个界面"的元素（或直接在中间状态图里连边），然后点顶栏「运行」。
事件栏会出现 `node_entered` → `edge_matched` → `action_executed`，画面上的识别框按"已确认（绿）/ 待确认（橙）"变色。

> 灰色不可点的按钮把鼠标停上去会说明原因（例如「状态图里还没有节点：先在画面栏点『框选』…」）。

### 坐标这件事（跨设备必须一致）

控制、录制、反馈用的是**同一套基准：当前画面的归一化坐标**。踩过的坑与现状：

| 设备 | 旋转后控制错位 | 框选能框到画面外 |
|---|---|---|
| Android（scrcpy） | 曾有：画布尺寸只在握手时读一次 → 已修（每帧同步） | 曾有 → 已修 |
| iOS（隧道 DVT） | **没有**（截图形状跟着转，实测横屏右上角下滑能拉出控制中心） | 曾有（前端共用代码）→ 已修 |
| macOS 窗口 | 无旋转概念；同类问题是"窗口被移动/改尺寸" → 手势开始时刷新几何 | 曾有 → 已修 |
| Mock | 无 | 曾有 → 已修 |

### macOS 本机窗口（把桌面应用的窗口当设备）

| 能力 | 实现 |
|---|---|
| 枚举 | `CGWindowListCopyWindowInfo` → **句柄**（`kCGWindowNumber`）、pid、App、标题、位置尺寸 |
| 选窗口 | 设备面板里展开「本机窗口（macOS）」→ 点一个直接连；也可以**直接输句柄**（`Mac:///?window=89`） |
| 抓图 | `CGWindowListCreateImage(…IncludingWindow, 句柄)` —— 只抓这个窗口，被别的窗口挡住也不影响 |
| 控制 | `CGEvent` 鼠标/键盘，坐标 = 窗口原点 + 归一化×窗口尺寸（屏幕点坐标，Retina 不影响） |

**控制方式两种**（`Mac:///?window=89&post=pid|global`）：

| 模式 | 你的鼠标/焦点 | 可靠性 | 实测 |
|---|---|---|---|
| `pid`（默认） | **完全不动**（CGEventPostToPid 直投目标进程） | 部分 App 会忽略直投事件 | 鼠标位置完全不变 ✓；Finder/活动监视器不响应 ✗ |
| `global` | 会激活目标 App、指针被挪到点击处（**手势结束自动放回原处**） | 和真人操作一样可靠 | 点击生效（内容差异 8.18）✓；鼠标回到原位置 ✓ |

想要"一边用它一边干活"就用默认的 `pid`；发现点了没反应就换 `global`。

**需要两个系统权限**（缺了会明确报错）：

- 系统设置 → 隐私与安全性 → **屏幕录制**：给运行 GamePilot 的程序打勾（否则抓图是空白）
- 系统设置 → 隐私与安全性 → **辅助功能**：控制别人的窗口需要它

实测（Finder 窗口 #89，920x436）：抓图 ✓、点击后画面差异 8.12 ✓、方向键差异 7.74 ✓。

**Windows 同构**：同一套控制器接口，把枚举/抓图/输入换成 `EnumWindows` / `PrintWindow`+`BitBlt` / `SendInput`
即可，上层（设备列表、坐标映射、脚本、录制）不用动。当前机器是 macOS，Windows 未实现也未验证。

### iOS（仅 17.4+，已在 iPhone 15 Pro Max / iOS 26.6.2 实测）

| 能力 | 实现 | 实测 |
|---|---|---|
| 投屏 | pymobiledevice3 用户态 RSD 隧道 + **DVT 截图循环** | 2796×1290、128ms/张 ≈ **7.8 fps** |
| 控制 | 同一条隧道上的 **CoreDevice HID**（触摸 0..65535 / Indigo 按键 / 虚拟键盘） | Home 键、点击、滑动都实测生效 |
| 发现 | `pymobiledevice3 usbmux list`，自动过滤低于 17.4 的设备 | iPhone 15 Pro Max（iOS 26.6.2）✓ |

**不需要 sudo、不需要切 USB 配置**（隧道是用户态的，`python -m gamepilot.devices.ios_usb` 可以测绘
每套配置的通路数）。

**为什么不用 QuickTime**（都实测过，别再走弯路）：

1. macOS 上 **ffmpeg/avfoundation 看不到** iOS 屏幕采集设备 —— 它属于 Continuity/External 类型，
   进程没有 `NSCameraUseContinuityCameraDeviceType` 声明就被系统隐藏（配置 1~6 全试过）。
2. pymobiledevice3 的隧道投屏 `DisplayService.startmediastream` 在 **iOS 26 上直接报
   "requires iOS 27.0 or later"**。
3. 把设备切到**配置 2 会让 usbmux 通路消失**（配置 2 只有 PTP + 音频 + HID）—— 这才是
   "QuickTime 独占设备、别的连不上"的真实机制。正常数据通路在**配置 6**，本实现不动它。

限制：`UserspaceRsdTunnel` 是进程级单例，**一个进程同时只能带一台 iOS 设备**（多台要拆进程）；
截图循环 ~8fps，适合自动化与模板匹配，不适合当高帧率监控看。

### 脚本（工程）目录

一个目录就是一个脚本：`graph.json`（状态图）+ `templates/`（录制下来的模板截图）。

- 顶栏左侧显示当前脚本目录（含节点数/识别器数），点它可切换或新建目录
- 切换目录会**热重载所有已连接设备的状态图**，运行中也不丢当前节点
- 默认在 `engine/projects/default/`；也可用 `GAMEPILOT_PROJECT_DIR` 指定

### 录脚本（把操作直接录成步骤）

1. 连上设备，在画面栏**框选**一个界面元素 → 自动建一个节点（这个界面）
2. 点画面栏的 **「录操作」**，然后在画面上正常操作：
   - 点一下 → 录成一步"点击"（带坐标）
   - 拖一下 → 录成一步"滑动"（带起止点与时长）
   - 「+等1s」按钮 → 录成一步"等待"
3. 换个界面后**再框选一次** → 上一步会自动接到这个新界面（A --动作--> B）
4. 点顶栏「运行」就是刚录下来的流程；事件栏能看到每一步

开「录操作」时操作照常发到手机上（跟手），只是额外记一步到脚本里。
条件默认是"在源界面才做"，想改成"无条件/限时等待"就点那条边改。

### 判断条件与基础操作

点中状态图里的一条边，底部会出现编辑器：

- **判断条件**：`且(all_of)` / `或(any_of)` / `非(none_of)` 勾选识别器标签，
  外加 `min_score` 分数门槛与 `限时等待ms`（进节点后最多等这么久，超时这条边不走并上报 `edge_timeout`）
- **动作**：点击 / 长按 / 滑动 / 等待 / 按键 / 输入文本；
  点击可以直接选"目标识别器"（跟着识别结果走），也可以用归一化坐标
- 保存后写回 `graph.json` 并热重载，运行中的状态机立刻用新条件

识别器面板里每个模板都有缩略图，**点一下切黑白** —— 黑白就是模板匹配真正用的样子。

### 图编辑器

- **+ 节点**：新建一个空节点，然后在底部给它挂识别器
- **拖节点**：按住就跟着鼠标走（拖动过程中不写盘）；**松手才写回 `graph.json`**，运行中也不会打断状态机
- **拖拽连线**：从节点右侧的小圆点拖到另一个节点即可连边（默认条件=源界面的识别器）
- **点节点**：底部出现节点编辑器（改名、挂/摘进入识别器、删除节点；删节点会连带删掉相关边）
- **点边**：底部出现边编辑器（判断条件 + 动作 + 优先级/冷却 + 删除）
- **重新布局**：按网格重排节点（引擎不存坐标，坐标是界面私有的）
- **运行/停止**：图栏头就能点，和顶栏是**同一个开关**；运行的是"当前这台设备"、读的是当前这份图 ——
  不点运行时引擎照样在识别（框/读数/阈值实时），只是不决策、不发动作；运行中改图不会打断它（热重载保留当前节点与运行态）

### 界面上各区是干什么的

| 区域 | 作用 |
|---|---|
| 顶栏 | 运行/停止、录制开关、设备选择器、**布局菜单（预设/恢复默认）**、引擎状态（点击可重试启动） |
| 设备标签条 | 每台已连接设备一个标签；单击切换活动设备，双击弹独立窗口，`+` 加设备 |
| 左栏「画面」 | 实时画面 + 识别框；**画面下方一条设备控制条**（控制 / 返回 / 桌面 / 最近任务 / 电源 / 录操作）；下半是识别读数（可上下拖） |
| 中栏「状态图」 | 节点=界面、边=动作、红色虚线=中断处理（recovery）；点边可看属性 |
| ↗ 状态图头 | **运行/停止（就近入口，和顶栏同一个开关）**、+ 节点、重新布局 |
| 右栏 | **Tab：脚本库 / 识别器**（识别器是阈值滑块，拖动即时重算分数） |
| 底栏 | node / tick / fps / 截图耗时，异常会变红；右侧四个按钮拉开**调试抽屉** |

**区域都能拖**：栏与栏之间的竖线左右拖 = 改宽度；栏内的横线上下拖 = 改高度
（画面/识别读数、画布/编辑坞、主区/调试抽屉）。比例会记住，下次启动还在；
拖乱了用顶栏「布局 → 恢复默认布局」，或双击任意分隔线让那一栏回到默认比例。
状态图的编辑坞没选中节点/边时会收成一条 28px 提示条，点节点或边自动展开。

**调试抽屉**（底栏右侧四个按钮，或点 Tab 名）：
「事件流」看状态机每一步、「日志」看引擎与界面的原始日志（不用再去翻终端）、
「控制台」手发一条 RPC 看返回、「时间轴」看当前帧/tick/fps。再点同一个 Tab 收起。

**多张状态图 = 多个脚本目录**：右栏「脚本库」里可以新建 / 复制 / 重命名 / 移除脚本，
点一行就切过去（会热重载所有已连接设备的状态图，运行中的不丢当前节点）。
一个目录 = 一张图（`graph.json` + 自己的 `templates/`），互不干扰；
移除是移到库根 `.trash/<名字>-<时间戳>/`，后悔了能捞回来。

### 常见问题

| 现象 | 怎么办 |
|---|---|
| 顶栏一直「引擎未连接」 | 点它重试一次；仍失败则 `cd engine && uv sync`（缺依赖会让引擎起不来），错误详情会显示在它旁边 |
| 顶栏写着「引擎旧进程 · 重启」/「读不到脚本库：未知方法: project.create」 | 引擎是应用启动时拉起的独立进程，代码更新后它还是旧的：点错误条或顶栏那个按钮**重启引擎**即可（会断开当前设备连接，重连一下）。新增引擎方法的开发者也别忘了把方法名加进 `lib/engine-methods.ts` |
| 设备列表是空的 | 手机没插好或没授权：终端跑 `adb devices`，状态应是 `device` 而不是 `unauthorized` |
| 点「运行」是灰的 | 悬停看原因：没选设备 / 设备没连上 / 状态图里没有节点 |
| 框选之后没反应 | 录制需要先连设备；界面顶部红条会提示 |
| 画面很卡、fps 只有 1~2 | 当前走 adb 截图通道（约 550ms/帧），够录制与慢速状态机，不够"看着顺滑"；scrcpy 通道是下一步 |
| 录纯色区域（血条之类） | 会自动改用**颜色识别器**（模板匹配对纯色不可靠），事件栏会写明 `mode: color` |
| 工程文件在哪 | `engine/projects/default/`（`graph.json` + `templates/`），可直接 git diff；用 `GAMEPILOT_PROJECT_DIR` 切工程 |

### 性能现状（真机实测：OPPO A57 / Android 6.0.1 / USB 2.0）

| 指标 | scrcpy 通道（默认） | adb screencap 回退 |
|---|---|---|
| 画面帧率 | 解码 ~28fps；按界面需要交付（单画面 10fps、多开每台 4~6fps、窗口不可见 0fps） | ~1.8fps（553ms/帧） |
| 每次取帧耗时 | 0.3ms（复用已解码帧） | 553ms |
| 点击 | **0.1ms**（控制 socket） | ~1030ms（`adb shell input tap` 要 fork 进程） |
| 连接耗时 | 1.6~2.5s | 1.8~3s |
| 录制一次模板 | ~10ms | ~10ms |
| 三台设备同时投屏 | USB 带宽共享，按 1.3s/台 估算 | 同左 |

- 走哪条通道在**底栏的 `link`** 里能看到；显示 `screencap（慢）` 说明 scrcpy 没起来
  （常见原因：设备端 jar 推送失败、视频编码器被占用、Android 版本过低）
- scrcpy **只在画面变化时才出帧**（静止画面会复用上一帧），所以 fps 会随画面活动浮动
- 界面不需要的帧不会被推：`device.stream` 让前端告诉引擎"这台的画面我看不看、看多少帧"，
  识别与状态机仍在引擎里照常跑 —— 多设备时这是避免卡顿的关键
- scrcpy-server（v3.3.4，Apache-2.0）已收进 `engine/vendor/`，不需要你单独装 scrcpy；
  也可以用 `GAMEPILOT_SCRCPY_SERVER` 指向自己的版本
