# GamePilot

面向**游戏**的状态机式自动化框架 —— 目标是 Airtest 的交互手感 + 挂机场景需要的状态感知与自愈能力。

- 桌面端：**Tauri 2**（Rust 壳）+ React 19 + TypeScript + Tailwind v4 + shadcn/ui
- 引擎：**Python 3.11+**（感知 / 决策 / 执行 / 事件），作为 sidecar 由壳守护
- 通信：**JSON-RPC 2.0 over stdio**（NDJSON 分帧）
- 设备：Android（adb → scrcpy）、Windows（DXGI + 虚拟 HID）、Mock（离线端到端）

> 当前状态：**项目骨架已完成**（工程配置、规范、契约、三栏布局占位、引擎链路自检）。
> 业务功能按 [`docs/DESIGN.md`](./docs/DESIGN.md) 的 M1~M5 里程碑推进。

## 快速开始

```bash
# 1. 前端依赖
pnpm install

# 2. 引擎依赖（会创建 engine/.venv）
cd engine && uv sync && cd ..

# 3. 启动桌面 App（开发态，自动拉起 Vite 与 Python 引擎）
pnpm tauri dev

# 只跑前端（浏览器里看布局，RPC 不可用）
pnpm dev
```

首次打开 App，点右上角 **「骨架自检（拉起引擎 + ping）」**：状态变绿即表示
`React → Rust → Python` 三段链路打通。

## 怎么用（三步）

```bash
cd ~/Desktop/gamepilot
pnpm install          # 只需第一次
cd engine && uv sync && cd ..   # 只需第一次
pnpm tauri dev        # 启动（窗口几秒后出现）
```

**第 1 步 · 连设备**
顶栏左侧写着「未连接设备」→ 点它 → 列表里选一台手机（或「Mock 合成设备」，不需要真机）→ **点那一行**即连接。
连上后顶栏变成设备名，画面栏开始出现画面。
连不上时界面会出现红条，直接写着原因（例如"未授权：在手机上确认允许 USB 调试"）。

**第 2 步 · 录一个界面元素**
点画面栏的「框选」→ 在画面上拖一个矩形 → 弹层里填名字（会自动建议）→「确定并写入状态图」。
画面栏底部的「识别读数」和右侧「识别器」面板会立刻显示它的**实时分数**。

**画面栏还能直接控制手机**（不用碰手机，坐标按画面算、拖动实时跟手）

- 点画面 = 轻触；在画面上拖拽 = **实时滑动**（拖动过程中逐事件发 move，跟手）
- 坐标按**实际画出来的画面**换算：`object-contain` 的黑边不参与控制，
  面板上会画一圈淡边框标出可点区域
- 工具栏右侧是功能键：← 返回 / ⌂ 桌面 / 最近任务 / 电源
- 左下角写「控制」的按钮可以关掉控制（关掉后画面只用于框选/点选录制，不会误触手机）
- 每次手动操作都会记一条事件（`manual_input`），在事件栏能看到坐标与耗时
- 走的是 scrcpy 控制通道：点击 ~0.1ms（`adb shell input tap` 要 ~1030ms）

**第 3 步 · 跑起来**
再录一个"下一个界面"的元素（或直接在中间状态图里连边），然后点顶栏「运行」。
事件栏会出现 `node_entered` → `edge_matched` → `action_executed`，画面上的识别框按"已确认（绿）/ 待确认（橙）"变色。

> 灰色不可点的按钮把鼠标停上去会说明原因（例如「状态图里还没有节点：先在画面栏点『框选』…」）。

### 脚本（工程）目录

一个目录就是一个脚本：`graph.json`（状态图）+ `templates/`（录制下来的模板截图）。

- 顶栏左侧显示当前脚本目录（含节点数/识别器数），点它可切换或新建目录
- 切换目录会**热重载所有已连接设备的状态图**，运行中也不丢当前节点
- 默认在 `engine/projects/default/`；也可用 `GAMEPILOT_PROJECT_DIR` 指定

### 判断条件与基础操作

点中状态图里的一条边，底部会出现编辑器：

- **判断条件**：`且(all_of)` / `或(any_of)` / `非(none_of)` 勾选识别器标签，
  外加 `min_score` 分数门槛与 `限时等待ms`（进节点后最多等这么久，超时这条边不走并上报 `edge_timeout`）
- **动作**：点击 / 长按 / 滑动 / 等待 / 按键 / 输入文本；
  点击可以直接选"目标识别器"（跟着识别结果走），也可以用归一化坐标
- 保存后写回 `graph.json` 并热重载，运行中的状态机立刻用新条件

识别器面板里每个模板都有缩略图，**点一下切黑白** —— 黑白就是模板匹配真正用的样子。

### 界面上各区是干什么的

| 区域 | 作用 |
|---|---|
| 顶栏 | 运行/停止、录制开关、设备选择器、引擎状态（点击可重试启动） |
| 设备标签条 | 每台已连接设备一个标签；单击切换活动设备，双击弹独立窗口，`+` 加设备 |
| 左栏「画面」 | 实时画面 + 识别框；「框选 / 点选」是录制入口；底部是识别读数 |
| 中栏「状态图」 | 节点=界面、边=动作、红色虚线=中断处理（recovery）；点边可看属性 |
| 右栏 | 事件流（含过滤）+ 时间轴 + 识别器阈值滑块（拖动即时重算分数） |
| 底栏 | node / tick / fps / 截图耗时，异常会变红 |

### 常见问题

| 现象 | 怎么办 |
|---|---|
| 顶栏一直「引擎未连接」 | 点它重试一次；仍失败则 `cd engine && uv sync`（缺依赖会让引擎起不来），错误详情会显示在它旁边 |
| 设备列表是空的 | 手机没插好或没授权：终端跑 `adb devices`，状态应是 `device` 而不是 `unauthorized` |
| 点「运行」是灰的 | 悬停看原因：没选设备 / 设备没连上 / 状态图里没有节点 |
| 框选之后没反应 | 录制需要先连设备；界面顶部红条会提示 |
| 画面很卡、fps 只有 1~2 | 当前走 adb 截图通道（约 550ms/帧），够录制与慢速状态机，不够"看着顺滑"；scrcpy 通道是下一步 |
| 录纯色区域（血条之类） | 会自动改用**颜色识别器**（模板匹配对纯色不可靠），事件栏会写明 `mode: color` |
| 工程文件在哪 | `engine/projects/default/`（`graph.json` + `templates/`），可直接 git diff；用 `GAMEPILOT_PROJECT_DIR` 切工程 |

### 性能现状（真机实测：OPPO A57 / Android 6.0.1 / USB 2.0）

| 指标 | scrcpy 通道（默认） | adb screencap 回退 |
|---|---|---|
| 画面帧率 | 解码 ~28fps；按界面需要交付（单画面 10fps、多开每台 4~6fps、窗口不可见 0fps） | ~1.8fps（553ms/帧） |
| 每次取帧耗时 | 0.3ms（复用已解码帧） | 553ms |
| 点击 | **0.1ms**（控制 socket） | ~1030ms（`adb shell input tap` 要 fork 进程） |
| 连接耗时 | 1.6~2.5s | 1.8~3s |
| 录制一次模板 | ~10ms | ~10ms |
| 三台设备同时投屏 | USB 带宽共享，按 1.3s/台 估算 | 同左 |

- 走哪条通道在**底栏的 `link`** 里能看到；显示 `screencap（慢）` 说明 scrcpy 没起来
  （常见原因：设备端 jar 推送失败、视频编码器被占用、Android 版本过低）
- scrcpy **只在画面变化时才出帧**（静止画面会复用上一帧），所以 fps 会随画面活动浮动
- 界面不需要的帧不会被推：`device.stream` 让前端告诉引擎"这台的画面我看不看、看多少帧"，
  识别与状态机仍在引擎里照常跑 —— 多设备时这是避免卡顿的关键
- scrcpy-server（v3.3.4，Apache-2.0）已收进 `engine/vendor/`，不需要你单独装 scrcpy；
  也可以用 `GAMEPILOT_SCRCPY_SERVER` 指向自己的版本
