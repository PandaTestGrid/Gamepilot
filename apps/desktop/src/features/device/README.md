# features/device — 画面栏

**职责**：设备连接与投屏的 UI 与状态；**不承担识别逻辑**。

计划内容（M1~M2）：

- `DevicePanel.tsx` — 画面容器、letterbox 缩放、十字准星与归一化坐标读数
- `useDeviceStream.ts` — 订阅引擎推送的 `engine.frame` 通知（JPEG），维护最近一帧
- `OverlayCanvas.tsx` — 识别框叠加（已确认 / 待投票 / 失败残影三态）
- `RecordingMarquee.tsx` — 框选/点选录制，产出归一化 `Rect` 交给 `features/recognizers`
- `RecordTools.tsx` — 素材区头部右侧那组录制工具（框选 / 点选 / 文字识别 / 录操作）

规则：

- 组件内**禁止**出现像素坐标：所有矩形都是 `[0,1]` 归一化，转像素只在引擎侧。
- 画面渲染不直接调用引擎：一律经 `src/lib/rpc.ts`。
- 不在本目录里写死颜色：三态语义色走 `index.css` 的 theme token（DESIGN.md §4.5）。

## 画面下方的设备控制条（只有导航键，居中）

`DeviceControls.tsx` —— 28px 横条：**导航键居中**，右侧一行状态提示。按键随平台变（`nav-keys.ts`，纯函数 + 单测）：

| 设备                                        | 控制条（导航键，居中）                   | 面板头（电源）                     |
| ------------------------------------------- | ---------------------------------------- | ---------------------------------- |
| Android / 模拟器                            | 返回 · 桌面 · 最近任务                   | 电源                               |
| iOS                                         | 只有 主页                                | 电源（侧边按钮）                   |
| 本机窗口（kind=`windows`：Windows / macOS） | **一个都没有**（并说明"没有实体导航键"） | **没有**（窗口设备没有实体电源键） |
| mock / 未知来源                             | 返回 · 桌面 · 最近任务                   | 电源                               |

- iOS 那一格只有 `主页` 不是省事：引擎 `devices/ios.py: NAMED_BUTTONS` 把 `back`/`recents`
  **都映射成 Home**，界面照搬 Android 的话，用户按「返回」其实按的是 Home；
- **居中是三栏网格**（`grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)]`）：左 1fr · 按键 · 右 1fr 放提示，
  两侧等宽所以按键是真居中 —— 用 `flex + justify-center` 会被右边那句提示顶偏；
- 它属于 **`SCREEN_LAYOUT` 的 `view` 面板**（画面那一格）：拖高"识别读数"时不会被推走；
- **位置跟着"当前设备的投屏框"走**（用户反馈后改的）：单画面时贴在画面框下面（`ScreenPane` 里
  紧跟 `SingleScreen`）；**多开时由 `ScreenGrid` 放进当前设备那一格**（画面与元信息栏之间），
  整片网格下面**不再**有第二条 —— 挂在外面时看不出 返回/桌面 按的是哪台设备，离画面也远。
  所以 `device-controls` 在多开里必须用 `within(grid-tile-<id>)` 去找，且**始终只有一条**；
- 设备没连上时按键变灰，`title` 里说明原因；状态全在 store（`session.store.pressKey`）。

## 面板头：OCR / 控制 / 多开 / 电源

在 `ScreenPane.tsx` 的 `PanelShell actions` 里（画面栏标题那一行）：

- `OCR`：**扫描当前画面文字**（`scanScreenForPick`，给"按文字点"取坐标用）；
- `控制`：开/关画面上的鼠标操作（`ui.store.controlMode`）；
- `多开`：网格视图（`device.store.gridView`）；
- `电源`：不是导航键，所以不占投屏下面那条；`powerKeyFor(kind)` 为 null 的设备（macOS 本机窗口）
  干脆不显示 —— 而不是摆一个点了必报错的按钮；
- 面板头是 `flex-wrap` + `min-h-7` 的：窄了会换行变高，不会把按钮压成竖排文字
  （由来见 `layout/PanelShell.tsx` 顶部注释）。

规则：**App 自己的开关 + 非导航的设备功能键放上面，导航键留下面对齐手机**。
分界的理由只有一条：让人一眼看出"哪些是 App 的、哪些是手机上的"。

## 录制工具：挂在「素材区」头部右侧（`RecordTools.tsx`）

框选 / 点选 / 文字识别 / 录操作是一组，**作用在画面上、产出的是素材**，
所以放在 `MaterialArea` 标题行的最右端（`素材区` 开关那一行）：

- 四个都是图标按钮（`record-marquee` / `record-pick` / `record-ocr` / `record-action`），点亮 = 正在录制；
- **收起素材区也留着**：素材区收起来画面更高，但"框一个模板"这件事还在，工具不能跟着列表一起消失；
- `录操作` 开着时它后面多出 `+等0.5s/1s/3s`（录一步等待属于"录操作"这件事，跟着它走）；
- 没连设备时**框选 / 点选 / 录操作置灰**并把原因写进 `title`；`文字识别` 不置灰 ——
  `beginOcrRecognizerCapture` 自己会给一句人话（没连设备时顺手打开设备选择器），
  "点了没反应"比报错更难查；
- 别把它搬回工作流详情坞：那里离画面和素材都远，跨栏找一个框选按钮的手感很差
  —— 详情坞的 `leading` 工具槽位就是因此删掉的（`features/graph/DockBar.tsx`）。

## 画面上的「录操作」辅助

`ScreenPane.tsx` 的 `SingleScreen` —— 只有**录操作**（`ui.store.recordActionMode`）开着时才在画面上画东西，
而且画什么必须和手势语义一致（判定在 `touch-gesture.ts`）：

| 场景                  | 画什么                                                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 正常控制：轻触 / 滑动 | **一个辅助都不画**（投屏要保持干净）。手势照常发给设备                                                                                 |
| 录操作·轻触           | 落点上**中心点 + 扩散环**（`animate-touch-ping`），抬手在同一位置再播一次 = "这一下录进去了"；整枚标记由 `animate-touch-fade` 收尾淡出 |
| 录操作·滑动           | **起点实心点 →（虚线）→ 终点空心圈 + 方向箭头**，拖动中落点实时更新 = "这一段会被录成 swipe"                                           |

规则：

- **辅助是「录操作」专属**（`recordActionMode` 为假时连轻触标记都不画）。
  别改成"总是画"或"正常控制也留个点"：投屏上多出来的东西用户一眼就嫌脏（真被要求删过两轮）；
- **两种形态互斥**（`TouchFeedback` 是联合类型，同一时刻只有一个）：
  曾经按下画一个、抬手在终点再画一个 —— 滑动就成了**两个分开的点击**，
  滑动抬手不补点击标记；
- 每个形状都带**暗色垫层**（`stroke-canvas` / `fill-canvas`）：投屏可能是白底亮画面，
  只画品牌蓝会糊在内容里；箭头的"方向"是滑动区别于点击的关键，别省；
- 轻触 / 滑动用**同一个阈值** `SWIPE_MIN_DISTANCE`，而且**按合位移判**，不按"有没有 move 事件"
  （轻触时手抖 1px 也会发 move）：否则会出现"画面上看着是点击、录下来却是滑动"；
- 辅助点用 `canvasPointToPixels` 按**实际画面区域**换算，不能用容器百分比 ——
  竖屏画面在横容器里有黑边，百分比画出来的点会飘到黑边上；
- 手势判定是**纯逻辑**，改动先看 `touch-gesture.test.ts` 与 `ScreenPane.test.tsx`
  （后者专门守"正常控制不画辅助"和"滑动抬手不补点击标记"这两条）。

## 多开网格：每一格都是**可交互画面**

`ScreenPane.tsx` 的 `ScreenGrid` —— `device.store.gridView=true` 时的网格视图。

**内核只有一份**：单画面与瓦片都用 `ScreenSurface`（`variant: 'single' | 'tile'`）。
坐标换算、手势判定、框选/点选、触控反馈全在里面，`variant` 只管外观
（占位文案、诊断日志前缀、要不要画识别框与帧浮层）。
**不许给瓦片另写一套** —— 以前瓦片就是一整个 `<button onClick={() => setActive(device.id)}>`，
画面区没有任何指针处理，于是控制模式（默认开）下点瓦片画面既不轻触也不滑动、
框选/点选在网格里静默失效（用户报的「设备多开时候点击功能失效」就是这个）。

交互规则（`controlEnabled` 决定"这一下要不要作用到设备上"，`onActivate` 负责切活动设备）：

| 状态            | 当前设备的瓦片（蓝边框）                                            | 别的瓦片                                                                                      |
| --------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 控制开 + 没录制 | 点 = 轻触、拖 = 滑动（坐标按**这一格自己的** imageBox，黑边不参与） | pointerdown **只切为当前设备**，这一次手势不发触控；切好后（它已成当前设备）再点/拖才是真控制 |
| 框选 / 点选     | 拖框 / 单击 → `beginDraft`                                          | 一样能拖：按下即切为当前设备，草稿落进**它**的状态图                                          |
| 控制关          | 点一下只切设备，永不发触控（瓦片老语义）                            | 同左                                                                                          |
| 头栏 / 脚栏     | 点一下只切设备（`grid-head-*` / `grid-foot-*`）                     | 同左                                                                                          |

**例外（否则"先切再操作"会退化成原始的"点了没反应"）**：`activeId` 指向的设备
**不在网格里**时（它掉线了，而 `device.store.failConnect` 只改状态、不动 activeId），
网格里没有任何一格是"当前设备" —— 这时按下就直接当控制用（`controlEnabled = isActive || !hasActiveTile`）。

为什么要"非当前设备第一下不发触控"：挂机场景里点别的瓦片绝大多数只是想换一台看，
直接发一次轻触就是**误触游戏**。所以规则是"先切、再操作"，提示语写在画面区的 `title` 里。

**录制草稿跟着设备走**（`RecordDraft.deviceId`）：`beginDraft` 记下按下时那台设备，
`commitDraft` 用它而不是现取 `activeId`。
规则背面是"浮层画在**草稿那台设备**的画面上"（`ScreenSurface` 的 `overlayForDraft`）——
在 A 上框完、随手点 B 看一眼、再点确定，仍然写进 A 的状态图；
否则 A 上框选可能写入 B 的状态图。
草稿归属的设备掉线、网格里没有它那一格时，`ScreenPane` 会挂一份**兜底浮层**
（`anchor=null`，停在右上角）：表单必须永远摸得到，不然草稿会卡在 store 里（Esc / 确定都够不着）。

其它约定：

- testid：`grid-tile-*` / `grid-head-*` / `grid-foot-*` / `grid-screen-*`（画面区），
  瓦片里 img 的 alt 仍是 `<设备名> 画面`；回归用例在 `ScreenPane.grid.test.tsx`；
- 瓦片**不能改成布局居中**：中间层只有绝对定位的 `<img>`（内容宽度 0），一居中就被压成 0 宽 ——
  当年"多开看不到投屏"的真凶，`items-stretch` 必须留着；
- 草稿表单（`RecordOverlay`）只画在**草稿那台设备**的格子里（`overlayForDraft`），
  否则 N 块瓦片会叠出 N 个一样的浮层；它没有画面时由 `ScreenPane` 的兜底浮层接管（见上一节）；
- 识别框与帧浮层只有单画面画：瓦片一格巴掌大，糊满框反而看不清（要看框就双击设备标签开独立窗口）；
- `返回 / 桌面 / 最近任务`（`DeviceControls`）长在**当前设备那一格**里（画面与元信息栏之间），
  切设备就跟着搬；整片网格下面**没有**第二条 —— 挂外面时看不出按的是哪台设备（用户反馈）；
- 既然当前格多了一行控制条，行高就有**下限**（`ROW_MIN_PX = 132`，`minmax(132px,1fr)` +
  网格 `overflow-auto`）：头栏/控制条/脚栏都是 `shrink-0`，矮面板里只有画面能被压 ——
  没有下限就会把当前格的画面压到接近 0（"多开看不到画面"的第二形态）。宁可网格滚动；
- 控制条挤进窄格时按键文字收成图标（`hidden @[210px]:inline`）：三个带文字的键约 195px，
  窄格（2 列 + 窗口不宽）会顶出格子，收成图标约 90px；完整说明仍在 `title` 里；
- 多开时每台 4~6fps（`App.tsx` 的推流策略），但**控制不走帧通道**，帧率低不影响点击跟手。

## 底部「识别读数」（筛选 / 改名 / 收起）

`ScreenPane.tsx` 的 `RecognizerReadout` —— 画面栏下半格那串识别器读数：

- **全部 / 命中 切换**：`命中 = state !== 'idle'`（待确认 + 稳定）。识别器一多，
  "这一帧谁在命中"才是要看的信息；两个按钮上都带计数，不用切过去数。
  选择存 `ui.store.readoutFilter`（换设备、面板重挂之后还在），默认 `all`（和以前一样）。
  筛完一条不剩时给**空态文案指路**（"切到「全部」看全部 N 个"），不是一片空白。
- **行内改名**：双击名字 → 输入框（内容全选）→ `Enter` 保存 / `Esc` 取消 / 点别处也算保存。
- **整区收起**：点标题（`识别读数`）收起/展开，也可以把上面的横线**拖到底**。
  状态在 `ui.store.readoutOpen`，尺寸由 `Panel` 的 `collapse/expand` 执行
  （和底部调试抽屉同一套做法）。收起后只留 26px 标题行，并显示"命中 N"作为唯一读数；
  **不能收到 0** —— 分隔线贴到面板底边就抓不住了（CONVENTIONS §12.6-6）。
  拖动折叠时 `Panel` 的 `onResize` 会把状态回写 store，否则标题上的箭头会和真实状态相反。

**这一列没有删除，也别加回去**：它是实时监控（分数每帧在跳），而删除是销毁性操作；
被引用时引擎会拒绝删除。
删除在 `features/recognizers/RecognizerPane.tsx`（右栏「识别器」Tab）—— 那里能同时看到
缩略图、阈值和"被谁引用"，被引用时按钮直接置灰。

规则：

- 提交改名只走 **blur 一条路**（`Enter` = 主动失焦）：两条路各提交一次会把同一个改名发两遍，
  第二遍必然报"识别器不存在"。输入框卸载时浏览器补的那个 blur 用 `finished` ref 挡掉。
- 校验：`features/recognizers/recognizer-name.ts` 是**纯逻辑**，规则和引擎的
  `core/graph.py: validate_recognizer_label` 一一对应（非空 / ≤48 / 不带 `/` `\` 与控制字符 /
  不用保留名 `always` / 不重名）。前端拦一道只是为了"即时反馈"，而且**校验不过不关输入框**
  （原因写在行里接着改）；**引擎才是权威**。
- 改名走 store 动作 `renameRecognizer`，引擎返回整张新图 → `applyGraph` 直接换掉本地图，
  **不要自己拼**（引用会被级联改过）；事件栏留一条 `recognizer_renamed`。

## 设备弹层（分类与交互）

| 文件                | 职责                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `DevicePopover.tsx` | 弹层外壳：搜索、分类 Tab、列表、Footer（刷新/高级），↑↓/Enter/Esc 键盘流转                                           |
| `device-kinds.ts`   | **纯逻辑**：分类 / 过滤 / 排序 / 搜索（`buildDeviceTabs` / `filterByTab` / `sortForDisplay` / `resolveTab`），有单测 |
| `DeviceRow.tsx`     | 一行设备：当前 / 已连接 / 未连接 / 失败 四种交互各不相同                                                             |
| `WindowList.tsx`    | 「本机窗口」Tab 的内容（Windows / macOS 通用）：枚举窗口 + 搜索 + 刷新 + 已绑定标记 + 前台/后台两档 + 权限提示 |

规则：

- **只显示有内容的分类**（空 Tab 会让人以为"设备不见了"）；分类计数来自实际设备列表。
- 本机窗口在引擎里是**一个伪设备（`macos:picker` / `windows:picker`）+ 一串窗口**两条数据路径：
  伪设备**不是可连设备**，只用来在 Tab 上有入口；真正要连的是 `macos:<句柄>` / `windows:<hwnd>`。
  Tab 统一叫「本机窗口」（id `window`），窗口列表走 `window.list`；Windows 行点击时按所选输入方式
  在 URI 上追加 `&post=global`（前台 SendInput）或 `&post=sync`（后台同步 SendMessage）。
  引擎仍支持 `post=message` / `post=hybrid` / `cursor=1`，需要时手写 URI（界面不再展示）。
- 点击语义按状态分：当前设备 = 无动作；已连接 = **切换**；未连接 = 连接；行尾按钮才是断开。
- `DeviceKind` 白名单在 `stores/device.store.ts` 里是**穷举 Record**：新增来源漏一行就编译不过
  （曾经漏了 `ios`，所有 iPhone 被降级成 `remote`，分类里看不到）。
- **模拟器多屏 = 一组可切换的窗口**：MuMu 把点开的应用放到独立虚拟屏上，引擎扫描时把主屏以外的屏展开成一行
  （id `android:<serial>:<屏号>`，URI 带 `display`，名字带屏号与顶层应用包名）。画面栏顶部的
  `EmulatorDisplayTabs` 按 adb serial 把它们归到同一组：已连接屏幕点一下切换画面与控制；未连接屏幕点一下连接并切换。
  即使暂时只发现主屏，也显示「模拟器窗口 · 主屏 · 添加屏幕」，新开 MuMu 标签页后展开它（展开即自动重新枚举）立即出现；普通单屏真机不显示。
  连接失败时保留原画面，错误仍在错误条/屏幕提示中。切屏不会替用户断开其他屏的自动化会话；并行连接仍受 4 台上限约束。
  具体协议见 `docs/rpc.md`「Android 多屏」。

## AI 识别弹窗（`YoloRecognizerDialog.tsx`）

AI 识别器 = 框示例 → 录制参考帧 → 实时检测看效果 → 保存成 `type: "yolo"` 的识别器。
组件拆在 `YoloVideoStage` / `YoloPlaybackToolbar` / `YoloRecordingPanel` / `YoloSettingsPanel`，
`useYoloRecording` 管录制：

- 左列：**画面**（冻结/实时帧 + 框示例叠加）→ **播放工具条**（检测/首尾帧/回放/跟随/刷新 + 回放 fps）；
- 左列下半：**录制面板**（录制按钮 + 标注/控制/清空 + 左=录制列表、右=帧时间轴）；
- 右列：设置栏（示例 / 识别器 / 检测参数 / 模型与环境），底部钉住「开始实时检测」；
- 底部一行：左边提示（保存条件 / 错误），右边「取消 / 保存识别器」。

录制是**引擎落盘**的（`recording.start` / `recording.meta` / `recording.frameAt`），不是前端攒帧：

- **边录边显示**：录制中每 350ms 轮询 `recording.meta`，时间轴按已录帧实时长出来，
  录制列表出现「录制中 · N 帧」；不用等停止才看到内容；
- **每一块都是这一帧**：轨道上缺图时按 `recordingId + 帧号` 向父层要图（`recording.frameAt`），
  绝不拿邻帧冒充、也不留一块块空白；录制中同样能取到已落盘的那一帧；
- 录制中拖动时间轴 = 回看这段录制的帧（`takingRef` 指向活 take）；停止后才生成正式 take。

按钮与 icon 规则（跟素材区同一套语言，改布局时别退回旧样式）：

- 所有图标按钮共用一个 `IconButton`：**24px 点按区、14px lucide、stroke 1.75**、hover=底色、
  disabled=40%、选中用 `bg-brand/20` + brand 图标（和素材区的框选/OCR 按钮一致），**不用实心色块**；
- 右栏输入框 / 下拉 / 按钮统一 28px 高、1px `line` 描边（以前下拉是 `bg-canvas/60` 无边框，
  和输入框不在一个语汇里）；
- 控制条内不再放装饰性竖线：分组之间只留间距；区域之间（header / 控制条 / 底部槽 / 设置栏 / footer）
  仍用 1px 描边；
- 拖框提示在画面底部**居中**（一次性的 coach mark），画面状态角标留在右上角。

**编辑模式不是只读**（素材区点铅笔进来）：回放条照常显示（没有缓冲时显示「参考帧」），
「刷新」重新取当前画面当背景，「实时」跟随最新画面，然后可以继续拖框追加示例；
状态角标会写「参考帧 · 可继续框示例」。保存仍走 `recognizer.update`（label 不变，引用不受影响）。
老识别器如果没存参考图, 编辑模式会直接退到当前画面 —— 不能因为背景图缺失就把拖框功能一起藏掉。

规则（每条都是踩过的坑）：

- **组件 ≠ 模型，不能放在一起抢位置**。组件是推理运行时（worker + torch，几十 MB~几 GB），
  模型是 `.pt` 权重。安装/更换组件在「模型与环境」自己的行（就绪时只剩「更换组件…」），
  导入模型在「模型」行（「导入模型…」）。标题栏不放安装按钮：之前「组件…」「添加模型…」
  两枚按钮挨在一起，用户分不清该点哪个。
- **帧缓冲是环形的**（引擎默认保留最近 30 帧）：弹窗打开后画面还在更新，
  `recognizer.frames.meta` 拿到的帧号很快就可能被挤掉。所有取帧都带 `nearest: true`
  （引擎返回帧号最接近的保留帧，旧引擎会忽略这个参数），前端拿到实际帧号后重同步进度条；
  还是取不到就退到最新帧。**「已被滚出缓冲」是正常现象，不能弹成红色报错** —— 只用底部
  一行瞬提示（`frameNote`，4 秒自动消失），红色留给真正的失败。
- 取帧是并发的：只让**最后一次**请求的结果上屏（`frameSeqRef`）；预取只进缓存、不直接换画面，
  否则回放会抢在光标前面跳帧。
- 拖框只在冻结画面上做：实时检测时画面在动，拖框层直接 `pointer-events-none`，
  避免框到的参考图和当时画面不是同一帧。
- 点「停止检测」时把**当前帧**冻成新快照（保留上一次的检测框和统计），
  否则结果框会挂在打开弹窗时的老画面上，看着像识别错位；反过来，点「实时」跟随或「回放」
  换的是另一帧，必须先清掉上一轮检测框，不然框会贴着旧位置随新画面漂移。
- 示例缩略图点击 = 暂时停用（`mark.enabled`），右上角悬浮按钮删除；右栏字号最小 11px
  （DESIGN §4.0），坐标提示、按钮说明这种一次性的字才用 10px。
- 弹窗是 `role="dialog"` + `aria-modal`，Esc 关闭；所有关键控件保留既有 `data-testid`
  （`yolo-label` / `yolo-detect-toggle` / `yolo-save` / `yolo-mark-toggle-*` …），回归在
  `YoloRecognizerDialog.test.tsx`。
