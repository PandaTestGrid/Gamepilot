# features/library — 工作区（工作区 › 工作流）

**职责**：管理"有哪些工作区、每个工作区里有哪些工作流"，
一个工作流 = 一个目录（`graph.json` + `templates/`）= 一张流程图。

层级（契约 `docs/WORKSPACE-CONTRACT.md` **v4**，只有两层）：

- **工作区 = 项目，同一个东西**：用户自己选的一个文件夹，可以有多个（列表按最近使用排序，
  名字由用户输、默认预填文件夹名，持久化在引擎的 config.json）；
- **工作流**挂在工作区下面，可以有多个；**不再有「项目」这一层**；
- 接入一个空文件夹时引擎**什么都不建**；「没有当前工作流」「没有当前工作区」都是一等状态。

| 文件 | 职责 |
|---|---|
| `WorkspaceLibraryPane.tsx` | 右栏「工作区」Tab 的**外壳**：错误行（含"引擎是旧进程 → 重启引擎"）+ 工作区区域 + 底部「当前：…」 |
| `WorkspacePanel.tsx` | **右栏区域的本体（不是浮层/弹框）**：头部 搜索/设置/＋（添加工作区 ⌘O）、工作区列表（整行 = 展开/折叠，像树）、当前工作区下的工作流（圆点 + 名字 + 相对时间 + 悬停改/复/删）、空态「＋ 新建工作流」 |
| `native-dialog.ts` | 调 Tauri 原生选目录（**动态 import + try/catch**；拿不到返回 null → 调用方退回手输） |
| `workspace-tree.ts` | 纯函数：把引擎返回的树/列表收窄成可渲染的形状 + 路径、绝对路径判断、相对时间、搜索（**必须单测**） |
| `WorkflowNameForm.tsx` | 内联命名表单（新建 / 改名 / 复制共用；不用浏览器原生 prompt，Tauri 里它是禁的） |
| `workflow-name.ts` | 工作流名规则纯函数（与引擎 `library.validate_name` 同一套，**必须单测**） |

规则：

- **右栏只有一套列表**：`WorkspacePanel` 就是那个 Tab 的内容。曾经它是个浮层、旁边还有个
  `WorkspaceTree` 渲染同一批目录 —— 用户看到两份真相，两者都已收敛成现在这一套（树已删除）。
- **引擎是唯一真源**：工作区列表来自 `workspace.list`，工作流来自 `workspace.tree`，
  `workflow.*` 回当前工作区刷新后的工作流列表，`workspace.add` / `workspace.remove` 回整棵树
  （见 `stores/library.store.ts`）；界面不做本地乐观更新。
- 切换工作流走 `session.store.switchProject`（会热重载所有已连接设备的状态图并保留运行态）；
  切换工作区走 `workspace.add`（引擎把当前工作流一起切过去）。
- 「＋工作流」**要输名字才建**（内联表单，v4 明确不许"点一下直接建"）；「＋」添加工作区是**两步**：
  ① 选文件夹（原生选目录，拿不到就手输绝对路径）→ ② 输工作区名字（默认预填文件夹名）→ 确认才登记。
- 删除工作区两个入口都要有：**删除（真删，不可恢复）** 与 **只从列表移除（不动文件）**；
  删除工作流走**行内二次确认**；浏览器原生 prompt / confirm 一律不用
  （Tauri webview 不可用）；真删须写明不可恢复。
- 删除是**真删除**（`shutil.rmtree`）：工作流目录；以及 `deleteFiles: true` 的整个工作区。
